# 대시보드를 어디에 둘까 (2026-08-24)

스트림릿 대신 **정적 페이지 한 장 + n8n**으로 간다.
`docs/설계_스트림릿을_걷어낼까.md` §7의 **B안**이다.

## 처음엔 GitHub Pages로 가려다 접었다 — 자리가 이미 임자가 있었다

**저장소 하나에 Pages 사이트는 하나뿐이다.** 그런데 이 저장소의 것은
이미 쓰이고 있다 — `main` 브랜치의 **LX MI 대시보드**다.

  · `main`은 이 저장소와 전혀 다른 프로젝트다(Vite/React/Tailwind).
  · `.github/workflows/deploy.yml`이 `dist`를 Pages에 올린다.
  · 56번 돌았고 마지막이 2026-08-24 07:51이다. **살아 있는 화면이다.**

내가 만들었던 `pages.yml`이 성공했으면 그 화면을 **통째로 갈아치웠을
것이다.** 그게 실패하고 있던 게 다행이었다(`github-pages` 환경이 `main`만
허용하는 것으로 보인다 — 잡이 스텝 0개로 막혔다). `concurrency` 그룹까지
`pages`로 같아서 저쪽 배포를 취소시킬 수도 있었다.

**브랜치를 새로 만들어도 안 된다.** 자리가 branch 문제가 아니라
"저장소당 하나"라서다. 그래서 그 워크플로는 지웠다.

## 그래서 화면도 n8n이 내려준다

```
 ┌───────────────────────────────────────────────┐
 │  n8n  GET /webhook/muwon                      │
 │   raw.githubusercontent.com에서 site/index.html│
 │   를 받아 그대로 돌려준다                       │
 └──────────────┬────────────────────────────────┘
                │ 같은 출처라 CORS가 없다
 ┌──────────────▼────────────────────────────────┐
 │  n8n  POST /webhook/muwon-balance             │
 │   열쇠 확인 → (토큰 캐시) → KIS 잔고조회 → 정리 │
 └──────────────┬────────────────────────────────┘
 ┌──────────────▼────────────────────────────────┐
 │  KIS 모의투자 — inquire-balance                │
 └───────────────────────────────────────────────┘
```

**원본은 계속 저장소에 있다.** n8n에 HTML을 복사해 두면 고칠 때마다 두
곳을 맞춰야 하고 언젠가 어긋난다. 받아오게 두면 `git push` 하나로 끝난다.

덤으로 **CORS가 사라졌다.** 화면과 자료가 같은 출처라 브라우저가 막을 일이
없고, 첫 화면에서 주소를 물을 필요도 없어져 **열쇠만** 받는다.

---

## 1. 왜 페이지에 자료를 안 두나

**이 저장소는 공개다.** `site/index.html`은 raw로 누구나 받을 수 있고,
n8n이 내려주는 화면도 주소만 알면 열린다. 계좌 스냅샷을 파일에 넣는
순간 보유 종목과 잔고가 공개되고, **그건 되돌릴 수가 없다**(캐시·크롤러).

그래서 파일에는 화면 그리는 코드만 두고, 숫자는 볼 때마다 웹훅에서
받아 온다. **열쇠가 없으면 숫자가 안 나온다.** 열쇠는 `localStorage`에 —
보는 사람 브라우저에만 있고 저장소에는 안 올라간다.

## 2. 왜 토큰을 캐시하나

KIS는 **토큰 발급을 자주 하면 403으로 막는다.** 실제로 막혔다 —
2026-08-24에 계좌 대조를 몇 분 사이에 네댓 번 돌렸더니 거부당했다.

페이지의 자동 갱신이 1분인데 매번 토큰을 새로 받으면 금방 막힌다.
그래서 워크플로가 받은 토큰을 `$getWorkflowStaticData`에 넣어 두고
**20시간 동안 재사용**한다(유효기간은 24시간인데, 경계에서 만료되면
화면이 이유 없이 비므로 20시간만 믿는다).

## 3. 웹훅이 돌려주는 모양

```json
{
  "현금": 9910035,
  "순자산": 9999135,
  "원가": 90100,
  "평가손익": -1000,
  "조회시각": "14:02:11",
  "종목": [
    { "종목": "HPSP(403870)", "평가손익": -1000, "수량": 2,
      "평균매입가": 45050, "현재가": 44550, "평가금액": 89100 }
  ]
}
```

조회에 실패하면 `{"오류": "..."}`만 돌려준다. **KIS는 실패해도 HTTP 200으로
답하고 `rt_cd`에 결과를 담기 때문에**, 그걸 그냥 넘기면 화면에 0원이 뜨고
그건 "돈이 없다"로 읽힌다.

현금은 **가수도정산금액**(`prvs_rcdl_excc_amt`)이다. 예수금 총액을 쓰면
오늘 산 것이 결제(T+2) 전까지 안 빠져서 이틀 동안 못 본다.

## 4. 남은 사람 손 — 하나뿐이다

열쇠도, Publish도 내가 해 뒀다. **KIS 자격증명만 사람이 넣어야 한다** —
비밀값이라 내가 만들 수도, 볼 수도 없다.

워크플로: **AutoTrading_계좌조회**
(https://sondullab.app.n8n.cloud/workflow/Ew7CMMjSThC1E42B)

두 HTTP 노드가 각각 **Custom Auth** 자격증명을 하나씩 쓴다. 앱키·시크릿은
같은 값이고 **넣는 자리만 다르다** — KIS가 토큰 발급은 본문(body)으로,
조회는 헤더(headers)로 받기 때문이다.

**「KIS 토큰 발급」 노드** — 이름 `KIS 모의투자 — 토큰발급용`:

```json
{ "body": { "appkey": "앱키", "appsecret": "앱시크릿" } }
```

**「KIS 잔고 조회」 노드** — 이름 `KIS 모의투자 — 조회용`:

```json
{
  "headers": { "appkey": "앱키", "appsecret": "앱시크릿" },
  "qs": { "CANO": "계좌번호앞8자리", "ACNT_PRDT_CD": "01" }
}
```

앱키·시크릿·계좌번호는 GitHub Secrets에 있는 것과 **같은 값**이다.
넣은 뒤 Publish를 한 번 더 눌러야 반영된다.

이 세션의 프록시가 `n8n.cloud`와 `github.io`를 막고 있어서 **내가 직접

사람이 한 번 열어 봐야 한다.

## 5. 정직하게 — 이 구조가 포기하는 것

**KIS 자격증명이 있는 곳이 셋으로 늘어난다**(GitHub Secrets, 운영 DB, n8n).
지금은 **모의투자 계좌**라 가짜 돈이고 손해 위험은 없다. 다만 나중에
실거래로 갈 때는 이걸 반드시 다시 따져야 한다 — n8n이 뚫리면 실제 주문을
낼 수 있는 열쇠를 쥐게 되는 것이다. 우리 안전장치(`verify_kis_order`가
실거래를 거부하는 것 등)는 **파이썬 안에만 있고 n8n에는 없다.**

또 하나: **이 페이지는 보기만 한다.** 킬스위치를 끄거나 설정을 바꾸는
것은 여기서 못 한다. 그건 시트와 텔레그램이 계속 맡는다 — 돈이 나가는
방향을 바꾸는 일에 화면을 하나 더 만들 이유가 없다.

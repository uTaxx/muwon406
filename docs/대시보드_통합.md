# 화면 하나로 모은다 (2026-08-24 밤)

## 왜 다시 만드나

관리 지점이 다섯이었다. 스트림릿(전략·기준), 구글 시트(승인·기록),
텔레그램(알림·버튼), n8n 화면(지금 손익), GitHub(실행 기록).

**이건 설계가 아니라 누적이다.** 필요할 때마다 하나씩 붙였고, 걷어내기로
한 것(스트림릿)을 안 걷어냈다. "관리를 여기저기 들어가서 하라는 건지"라는
말이 정확한 진단이다.

목표는 **둘**이다 — 화면 하나와 텔레그램 알림.

| 지금 | 옮겨 갈 곳 |
|---|---|
| 스트림릿 — 전략·기준·킬스위치 | **대시보드 「전략과 기준」 탭** |
| 시트 — 승인 칸 | **대시보드 「오늘 승인」 탭** (텔레그램 버튼도 그대로 둔다) |
| 시트 — 매매기록·성적 | **대시보드 「기록」 탭** (원본은 시트에 계속 쌓인다) |
| n8n 화면 — 지금 손익 | **대시보드 「지금 손익」 탭** |

시트는 **기록 보관과 감사용으로 뒤로 물러난다.** 지우지 않는다 — 사람이
직접 열어 확인할 수 있다는 것이 이 시스템의 안전장치 중 하나다.

## 어디에 있나

```
sdlab_trading/dashboard/     ← 화면 셋(html·css·js). 빌드 없음
  index.html                   구조
  style.css                    색·글꼴 토큰이 맨 위에 모여 있다
  app.js                       웹훅 호출과 그리기

.github/workflows/deploy-dashboard.yml   ← Pages에 그대로 올린다
```

**빌드 단계를 일부러 두지 않았다.** 스트림릿에서 겪은 것이 "배포가 밀려서
다른 화면을 본다"였고, 빌드는 그런 밀림이 생기는 자리다. 올릴 것이 그대로
올라가면 어긋날 구석이 없다.

주소는 배포 후 **https://utaxx.github.io/sdlab_trading/** 이 된다.

## 웹훅 규약

화면은 상태를 안 들고 있다. 열 때마다 물어보고 그린다.

### 이미 도는 것

```
POST {n8n}/webhook/muwon-balance   { 열쇠 }
  → { 현금, 순자산, 원가, 평가손익, 조회시각, 종목: [...] }
```

### 새로 만들 것 — 창구 하나로 모은다

```
POST {n8n}/webhook/sdlab   { 열쇠, 무엇, ...인자 }
```

**왜 하나인가**: 열쇠 검사도, 허용 출처도 한 곳에서만 보면 된다. 여럿으로
나누면 하나를 빠뜨리고 **빠뜨린 줄도 모른다.** 지금 계좌조회 웹훅의 허용
출처가 옛 주소로 남아 있던 것이 정확히 그 사고였다.

| `무엇` | 인자 | 돌려줄 것 |
|---|---|---|
| `승인목록` | — | `{ 날짜, 후보: [{종목코드, 종목명, 섹터, 수량, 예상가, 승인}] }` |
| `승인` | `종목코드`, `값`(`"Y"`\|`"N"`\|`""`) | `{ 된것: true }` |
| `기록` | — | `{ 승률, 손익비, 최대낙폭, 거래: [{종목, 손익, 수익률, 수량, 산값, 판값, 기간}] }` |
| `기준` | — | `{ 매매켜짐, 전략, 전략들: [{키, 이름, 설명}], 손절, 비중, 동시보유 }` |
| `기준저장` | `바꿀것: {...}` | `{ 된것: true }` |

실패는 전부 `{ "오류": "사람이 읽을 문장" }` 로 돌려준다. **HTTP 200에
오류를 담아도 화면이 알아듣는다** — KIS가 그렇게 답하기 때문에 이미 그
모양을 다루고 있다.

### 창구가 없을 때

지금은 `/webhook/sdlab`이 없다. 그러면 화면은 **예시 자료를 그리고 예시라는
것을 화면에 밝힌다.** 조용히 가짜를 보여 주는 것이 제일 나쁘다. 예시일
때는 누르는 단추가 전부 잠긴다 — 저장되지 않을 것을 누르게 두면 안 된다.

## n8n에 만들 것

`AutoTrading_계좌조회` 워크플로에 웹훅을 하나 더 붙이는 것이 가장 간단하다.
열쇠 검사 코드가 거기 이미 있다.

```
Webhook(POST /webhook/sdlab, allowedOrigins: *, responseMode: responseNode)
  → Code: 열쇠 확인 + 무엇 꺼내기
  → Switch(무엇)
      ├ 승인목록  → Google Sheets: 승인대기 탭 읽기      → 모양 맞추기 → 응답
      ├ 승인      → Google Sheets: 승인 칸 갱신          → { 된것: true }
      ├ 기록      → Google Sheets: 매매기록·성적 읽기    → 모양 맞추기 → 응답
      ├ 기준      → Google Sheets: 설정 탭 읽기          → 모양 맞추기 → 응답
      └ 기준저장  → Google Sheets: 설정 탭 갱신          → { 된것: true }
  → (열쇠 틀림) → 403 { "오류": "열쇠가 맞지 않습니다." }
```

**판단은 여기서 하지 않는다.** n8n은 시트를 읽고 쓰는 것까지다. 무엇이
유효한 승인인지(빈 칸은 거부, 어제 승인은 무효, 목록 밖은 무시)는
`src/muwon/cloud/approval.py`가 정하고, 그 규칙은 매수하는 쪽에서 돈다.
**화면에서 누른 것이 곧 매수가 아니다** — 09:05에 파이썬이 다시 판단한다.

> 이 세션에서 n8n을 *바꾸는* 도구 호출이 자동 승인 심사에 막혀 있어서
> 내가 못 만들었다. 읽기와 실행은 되므로, 만든 뒤 제대로 됐는지는 내가
> 읽어서 확인할 수 있다.

## 켜기 전에 사람이 할 것 — 하나뿐

**Settings → Pages → Source 를 `GitHub Actions`로.**

이 저장소는 Pages 자리가 비어 있으므로 다른 화면을 밀어내지 않는다.

> 이건 내가 못 켠다. GitHub 연동에 Pages 설정 권한이 없다 — 같은 이유로
> 저장소 만들기도 403이었다.

### 0초 만에 실패하고 로그가 없다면 — 워크플로 파일부터 의심한다

첫 배포 둘(#1·#2)이 **0초 만에, 잡이 하나도 안 잡힌 채** 실패했다.
클릭해 들어가도 로그가 없다.

**나는 이걸 "Pages를 안 켜서"라고 단정하고 여기 그렇게 적었다. 틀렸다.**

진짜 원인은 워크플로 파일이었다.

```yaml
- id: 배포                                  # ← 한글 id
  url: ${{ steps.배포.outputs.page_url }}    # ← 그걸 참조
```

**GitHub Actions 표현식 파서는 한글 식별자를 못 읽는다.** 파일이 통째로
파싱에 실패해서 잡이 배정조차 안 됐다.

```
(Line: 43, Col: 12): Unexpected symbol: '배포'
```

이 오류는 **Actions 화면에 안 나온다.** API로 워크플로를 실행해 보고서야
나왔다. 화면에서는 Pages 미설정과 겉모습이 완전히 똑같다.

**교훈**: `id`와 표현식은 영문으로 둔다. 사람이 읽는 `name:`은 한글 그대로
둬도 된다 — 파서를 타지 않는 자리다.

그리고 **0초 실패는 "환경 문제"가 아니라 "파일이 안 읽힌다"부터 본다.**
잡이 안 잡혔다는 것은 GitHub이 그 파일로 무엇을 해야 할지 몰랐다는 뜻이다.

## 아직 안 한 것

**디자인이 임시다.** MI 수집 대시보드를 참조하기로 했는데 그 화면을 아직
못 봤다 — 계정에 보이는 저장소가 `muwon406`과 빈 `LX-Group` 둘뿐이라
찾을 수가 없었다. 지금 색과 글꼴은 **자리를 채워 둔 것**이다.

바꿀 때 손댈 곳은 `dashboard/style.css` **맨 위 토큰 블록 하나**다.
컴포넌트는 전부 토큰만 참조하므로 그 위쪽만 갈아 끼우면 화면 전체가 바뀐다.

정한 것 하나: **오르면 빨강, 내리면 파랑**(한국 증시 관례). 이건 취향이
아니라 읽는 사람의 습관이라 디자인이 바뀌어도 유지한다.

## 확인한 것

Chromium으로 폰(390px)·PC(1280px), 밝은 테마·어두운 테마, 그리고
**창구가 있을 때와 없을 때**를 각각 띄워 확인했다.

- 창구 없을 때: 예시 배너가 세 탭 모두에 뜨고 단추가 잠긴다
- 창구 있을 때: 배너 없이 진짜 자료, 단추 열림
- 어느 폭에서도 가로 스크롤이 생기지 않는다
- JS 오류 없음

**승인 목록은 표가 아니라 카드다.** 처음엔 표로 만들었는데 폰에서 승인
단추가 가로 스크롤 뒤로 숨었다. **하루 중 사람이 손대는 자리가 거기
하나뿐인데** 그게 안 보이면 화면을 만든 의미가 없다.

# 대시보드를 깃허브에 (2026-08-24)

스트림릿 대신 **GitHub Pages에 올린 정적 페이지 한 장 + n8n 웹훅**으로 간다.
`docs/설계_스트림릿을_걷어낼까.md` §7의 **B안**이고, MI 수집 시스템이 쓰는
구조와 같다.

```
 ┌───────────────────────────────────────────────┐
 │  GitHub Pages — site/index.html               │
 │   공개. **자료가 하나도 없다.** 화면만 그린다.  │
 │   받아올 주소·열쇠는 보는 사람 브라우저에만     │
 └──────────────┬────────────────────────────────┘
                │ POST {열쇠}
 ┌──────────────▼────────────────────────────────┐
 │  n8n 웹훅 — AutoTrading_계좌조회               │
 │   열쇠 확인 → (토큰 캐시) → KIS 잔고조회 → 정리 │
 └──────────────┬────────────────────────────────┘
                │
 ┌──────────────▼────────────────────────────────┐
 │  KIS 모의투자 — inquire-balance                │
 └───────────────────────────────────────────────┘
```

---

## 1. 왜 페이지에 자료를 안 두나

**이 저장소는 공개다.** `site/`에 올린 것은 그대로 세상에 나가고,
GitHub Pages도 공개다. 계좌 스냅샷 JSON을 거기 두는 순간 보유 종목과
잔고가 공개되고, **그건 되돌릴 수가 없다**(캐시·크롤러).

그래서 페이지는 화면 그리는 코드만 담고, 숫자는 볼 때마다 웹훅에서
받아 온다. 받아올 주소와 열쇠는 `localStorage`에 — 보는 사람 브라우저에만
있고 저장소에는 안 올라간다.

배포 워크플로(`pages.yml`)에 검사를 하나 뒀다. `site/`에 html·css·js·
이미지가 아닌 파일이 있으면 **배포를 멈춘다.** 나중에 누가 스냅샷을
거기 두는 실수를 막으려는 것이다.

## 2. 왜 토큰을 캐시하나

KIS는 **토큰 발급을 자주 하면 403으로 막는다.** 실제로 막혔다 —
2026-08-24에 계좌 대조를 몇 분 사이에 네댓 번 돌렸더니 거부당했다.

페이지의 자동 갱신이 1분인데 매번 토큰을 새로 받으면 금방 막힌다.
그래서 워크플로가 받은 토큰을 `$getWorkflowStaticData`에 넣어 두고
**20시간 동안 재사용**한다(유효기간은 24시간인데, 경계에서 만료되면
화면이 이유 없이 비므로 20시간만 믿는다).

## 3. 웹훅이 돌려주는 모양

```json
{
  "현금": 9910035,
  "순자산": 9999135,
  "원가": 90100,
  "평가손익": -1000,
  "조회시각": "14:02:11",
  "종목": [
    { "종목": "HPSP(403870)", "평가손익": -1000, "수량": 2,
      "평균매입가": 45050, "현재가": 44550, "평가금액": 89100 }
  ]
}
```

조회에 실패하면 `{"오류": "..."}`만 돌려준다. **KIS는 실패해도 HTTP 200으로
답하고 `rt_cd`에 결과를 담기 때문에**, 그걸 그냥 넘기면 화면에 0원이 뜨고
그건 "돈이 없다"로 읽힌다.

현금은 **가수도정산금액**(`prvs_rcdl_excc_amt`)이다. 예수금 총액을 쓰면
오늘 산 것이 결제(T+2) 전까지 안 빠져서 이틀 동안 못 본다.

## 4. 켜는 순서

### 4-1. GitHub Pages 원본을 바꾼다 (사람만 할 수 있음)

저장소 → **Settings** → 왼쪽 **Pages** → **Build and deployment**의
**Source**를 `Deploy from a branch`에서 **`GitHub Actions`**로 바꾼다.

지금은 브랜치 배포로 잡혀 있어서 배포가 실패한다. 이 설정을 바꾸는 API는
이 세션의 프록시가 막고 있어서(403) 대신 못 해 준다.

바꾼 뒤 Actions → **대시보드 배포 (GitHub Pages)** → Run workflow.
주소는 **https://utaxx.github.io/muwon406/** 이다.

### 4-2. n8n 자격증명 2개 (사람만 할 수 있음 — 비밀값이라)

워크플로: **AutoTrading_계좌조회**
(https://sondullab.app.n8n.cloud/workflow/Ew7CMMjSThC1E42B)

두 HTTP 노드가 각각 **Custom Auth** 자격증명을 하나씩 쓴다. 앱키·시크릿은
같은 값이고 **넣는 자리만 다르다** — KIS가 토큰 발급은 본문(body)으로,
조회는 헤더(headers)로 받기 때문이다.

**「KIS 토큰 발급」 노드**에 붙일 것 — 이름 `KIS 모의투자 — 토큰발급용`:

```json
{ "body": { "appkey": "앱키", "appsecret": "앱시크릿" } }
```

**「KIS 잔고 조회」 노드**에 붙일 것 — 이름 `KIS 모의투자 — 조회용`:

```json
{
  "headers": { "appkey": "앱키", "appsecret": "앱시크릿" },
  "qs": { "CANO": "계좌번호앞8자리", "ACNT_PRDT_CD": "01" }
}
```

앱키·시크릿·계좌번호는 GitHub Secrets에 있는 것과 **같은 값**이다.

### 4-3. 열쇠를 정한다

**「열쇠가 맞나」** 노드를 열어 오른쪽 값
(`AAA-여기에-정한-열쇠를-넣으세요-BBB`)을 아무 긴 문자열로 바꾼다.
주소를 아는 사람이 열어도 이 값이 없으면 계좌가 안 보인다.

### 4-4. Publish

**저장만으로는 웹훅 주소가 살지 않는다.** 오른쪽 위 Publish를 눌러야 한다.

웹훅 주소: `https://sondullab.app.n8n.cloud/webhook/muwon-balance`

### 4-5. 페이지 첫 화면에 넣는다

https://utaxx.github.io/muwon406/ 를 열면 연결 화면이 뜬다.
위 웹훅 주소와 4-3에서 정한 열쇠를 넣고 저장하면 끝이다.
폰에서 홈 화면에 추가해 두면 앱처럼 쓸 수 있다.

## 5. 정직하게 — 이 구조가 포기하는 것

**KIS 자격증명이 있는 곳이 셋으로 늘어난다**(GitHub Secrets, 운영 DB, n8n).
지금은 **모의투자 계좌**라 가짜 돈이고 손해 위험은 없다. 다만 나중에
실거래로 갈 때는 이걸 반드시 다시 따져야 한다 — n8n이 뚫리면 실제 주문을
낼 수 있는 열쇠를 쥐게 되는 것이다. 우리 안전장치(`verify_kis_order`가
실거래를 거부하는 것 등)는 **파이썬 안에만 있고 n8n에는 없다.**

또 하나: **이 페이지는 보기만 한다.** 킬스위치를 끄거나 설정을 바꾸는
것은 여기서 못 한다. 그건 시트와 텔레그램이 계속 맡는다 — 돈이 나가는
방향을 바꾸는 일에 화면을 하나 더 만들 이유가 없다.

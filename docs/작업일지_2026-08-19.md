## 어젯밤에 한 일 — 큰 덩어리 넷

### ① 섹터 8개·종목 50개를 정하고, 코드를 전부 검증했습니다

말씀하신 섹터 목록으로 만들었습니다(우주항공은 방산에 합침).

**그리고 50개 종목코드를 실제 시세로 전부 조회해 봤습니다.** 코드 한 자리가
틀리면 엉뚱한 회사를 사는데, 그건 주문이 나간 뒤에야 드러나기 때문입니다.

**네 가지가 걸렸습니다.**

| 무엇 | 어떻게 했나 |
|---|---|
| 엘앤에프가 코스닥이 아니라 **코스피** (이전함) | 고침 |
| 삼익THK 거래대금 **4억** | 껐음 |
| **구리는 국내 ETF로 살 수 없음** (최대 11억) | 매매 대상에서 뺌 |
| 금·은도 쓸 만한 게 하나씩뿐 | ACE KRX금현물(225억), KODEX 은선물(52억)만 남김 |

**구리 결론이 중요합니다.** 국내 구리 ETF는 거래가 거의 없습니다
(TIGER 구리실물 11억, KODEX 구리선물 4억). 그래서 **구리는 매매하지 않고
경기 신호 지표로만** 씁니다.

### ② 시장 상태 → 섹터 전망을 만들고 → **기각했습니다**

이게 어젯밤 작업의 대부분이고, 결론이 부정적입니다.

**만든 것**

1. 코스피 **30년**(7,304일) + 금·구리·환율·미금리로 날짜별 장 상태를 숫자로
2. 섹터 지수를 **그 시점에 있던 종목만으로** 만들기
3. **지금과 비슷했던 과거**를 찾아 그 뒤 20일 분포 내기
4. 낸 전망과 실제 결과를 짝지어 **채점**하기

**검증 방법 — 2개월 기다리지 않았습니다**

과거 날짜마다 전망을 내고 실제로 어떻게 됐는지 채웠습니다.
전망을 낼 때 **그날 이후 데이터는 안 씁니다.**

> 2010~2025, 483개 날짜 × 10개 대상, **결과가 나온 전망 2,308건**

**결과**

| | |
|---|---|
| 방향 적중률 | **51.8%** |
| 그냥 찍었다면 | **56.3%** |

**아홉 대상 전부** 기준선보다 못했습니다.

**그리고 더 나쁜 것 — 위험 칸이 거꾸로였습니다**

설계상 **'아주 나빴을 때' 칸을 보고 비중을 정할** 참이었습니다.

| 예측한 하위10% | 건수 | 실제 중앙 | 뚫린 비율 |
|---|---|---|---|
| −15% 아래 (**가장 위험**하다고 본 날) | 63 | **+5.4%** | 6% |
| −10~−6% | 840 | +0.8% | 11% |
| −3% 위 (**가장 안전**하다고 본 날) | 313 | **+0.5%** | **33%** |

**위험하다고 본 날이 오히려 +4.9%p 더 좋았습니다.** 안전하다고 본 날이
세 배 더 자주 뚫렸습니다(목표는 어디서나 10%).

**설계대로 썼다면 손해였습니다** — 비중을 줄여야 할 때가 아니라
**늘려야 할 때** 줄였을 겁니다.

**왜 그랬냐면**: 지표가 "변동성 높고 고점 대비 많이 빠진 상태"를 위험으로
읽는데, 그건 대개 **이미 떨어진 뒤**입니다. 그 뒤엔 반등이 잦았습니다.
**앞으로 올 위험이 아니라 지나간 위험**을 재고 있었습니다.

**"거꾸로니까 뒤집어 쓰자"는 안 했습니다.** 15년 데이터를 보고 부호를
맞추는 게 곧 과최적화입니다.

### ③ 대시보드를 걷어내는 준비를 했습니다

말씀하신 대로 **깃허브 + n8n + 구글 시트**로 갈 수 있는지 따져 봤습니다.
결론은 **된다, 그리고 그쪽이 낫다**입니다.

근거는 이번 세션 기록 자체입니다. 스트림릿 때문에 한 일곱 가지 중 **다섯이
기능이 아니라 "화면을 살려 두느라"** 한 일이었습니다.

옮길 곳을 하나씩 대조했더니 **대체 안 되는 게 하나도 없고 대부분 나아집니다.**

지금 1단계(시트에 설정 넣기)까지 끝났습니다. 스트림릿은 아직 그대로 둡니다 —
**2주 동안 시트만 보고 지낼 수 있는지 확인한 뒤**에 걷어냅니다.

### ④ n8n을 시계로 쓰는 설계를 정리했습니다

n8n 클라우드 상시 가동을 확인했고, **n8n = 시계, GitHub Actions = 일꾼**으로
역할을 나눴습니다.

핵심은 GitHub cron은 몇십 분씩 늦지만 **`workflow_dispatch`는 안 늦는다**는
것입니다. 그래서 **15:20 마감 전 청산이 가능해집니다** — cron으로는 못 하던
것이고 이게 제일 큽니다.

**규칙 하나를 못 박았습니다: n8n은 시각을 부르는 것 외에 아무 판단도 하지
않습니다.** 판단이 두 군데로 나뉘면 백테스트와 실거래가 또 어긋납니다.

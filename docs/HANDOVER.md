## 1. 지금 어떤 상태인가

### 대시보드 (`public/lxgroup-mi/hub.html`)

주소: <https://utaxx.github.io/muwon406/lxgroup-mi/hub.html>

메뉴 구조가 **계열사 중심**으로 바뀌었다.

```
헤더 버튼:  키워드 신청/변경 · AI 학습 데이터 · 대시보드 설정 · 사용 매뉴얼

왼쪽 메뉴:  Home
            키워드 뉴스
            특정 키워드 검색
            계열사 현황        ← 그룹 실적 + (계열사 선택 시) 경쟁사 성과 + 리스크 관리
            시장 지표          ← 계열사 줄을 공유하는 별도 메뉴
            자본시장 딜 현황   ← [주요 공시] DART + [관련 보도] 자본시장 계열 뉴스

계열사 화면 = 왼쪽 본문(그룹 실적 / 경쟁사 성과 + 리스크 관리)
              + 오른쪽 계열사 줄 [그룹 전체][인터][판토스][하우시스][글라스][세미콘][MMA][홀딩스]
              (처음 열리는 것은 「그룹 전체」 = 그룹 실적)
```

- 계열사 선택은 **하나만** 있다(`coTab`). 경쟁사와 시장 지표가 이 값을 공유한다.
  계열사 화면에서 실제로 켜는 칸은 `coPick`이고(`그룹` 또는 계열사 이름),
  계열사를 고르면 `coTab`도 같이 따라간다.
- 이름을 「계열사 들여다보기」에서 **「계열사 현황」**으로 바꿨다(2026-09-07).
- **그룹 실적**(`co-group`)이 기본 진입 탭이고, 이 탭만 계열사를 가리지 않는다. `경쟁사` 시트에서 `우리편`인
  줄만 모아 `compBlocks(것들, '그룹')`로 그린다 — 블록 렌더러는 경쟁사와 같고,
  열쇠 앞에 `그룹`을 붙여 펼침·기간·보기 상태만 따로 둔다. 이 탭에서는
  `#coTabs`(계열사 선택 줄)를 감춘다.
- 경쟁사 성과에서 **「우리」 배지와 붉은 띠를 없앴다**(2026-09-07). 회사 정렬도
  매출 규모 순 하나로 바꿨다. 우리 회사만 보는 자리는 그룹 실적 탭이다.
- 공통 지표(환율·금리 등)는 계열사를 바꿔도 시장 지표 탭 아래쪽에 항상 표시된다.
- 마지막에 본 계열사와 하위 탭은 localStorage에 저장된다
  (`lx-co` · `lx-co-pick` · `lx-deal-pick`).
- **탭을 옮길 때 주소에 `?tab=` 을 써 넣지 않는다**(2026-09-08). 써 넣으면
  주소창을 복사해 건네준 링크가 「그 사람이 마지막에 보던 탭」으로 열린다 —
  링크를 받은 사람은 Home 부터 보고 싶어 한다. 주소에 `?tab=` 이 적혀 들어온
  경우(사용설명서의 바로가기)는 그대로 그 탭을 연다. 같은 까닭으로 옛 주소
  스텁(`index.html`·`articles.html`)도 `?tab=apply`·`?tab=search` 로 보내지 않고
  Home 으로 보낸다.
- **새로고침만은 보던 탭으로 돌아온다**(같은 날 이어서 고침). 링크와 새로고침을
  가르지 않았더니, 설정을 바꿔 놓고 새로고침한 사람이 매번 Home 으로 튕겼다.
  `performance.getEntriesByType('navigation')[0].type === 'reload'` 로 가르고,
  보던 탭은 `lx-tab` 에 적어 둔다 — 주소에 안 넣으므로 남에게 건네주는 링크에는
  묻어 나가지 않는다.
  (설정값 자체(`lx-cfg`)는 처음부터 제대로 남고 있었다. 판 3 설정을 심어 두고
  판올리기까지 태워 본 결과 카드 켜기·차례·폭·기준·뉴스수가 전부 유지된다.)
- 구 주소 `?tab=comp`, `?tab=risk`는 계열사 화면으로 연결된다. `?tab=index`는
  이제 시장 지표가 왼쪽 메뉴에 있으므로 그대로 그 메뉴다. `?co=글라스`로 계열사를
  직접 지정할 수 있다.

### 첫 화면(Home)

카드는 모두 `#tab-home`의 직계 자식이고, `설정보이기()`가 `appendChild`로 사용자가
정한 순서대로 다시 배치한다. 기본 순서:

1. **공통 지표** — 환율·금리 등. 아침에 제일 먼저 보는 값이라 맨 위
2. **주요 뉴스** — 가장 최근 수집분 중 메일 발송 기준을 통과한 기사.
   **총점(중요도+관련성+긴급성, 3~15) 내림차순**으로 세우고 기본 5건만 펼친 뒤
   나머지는 「나머지 N건 더보기」로 접는다. 총점이 같으면 최신 기사가 앞
   (`Array.sort`가 안정 정렬이라 날짜순 배열을 총점으로 다시 세우면 자동으로 그렇게 된다)
3. 계열사 카드 (경쟁사 n곳 · 지표 n개 · 최근 7일 기사 n건 + 변동폭 최대 지표 1개)
4. **자본시장 딜**(절반 폭) — 지분 거래·합병분할·영업자산·계열사경쟁사 네 숫자 + 다섯 줄.
   다섯 줄은 계열사·경쟁사가 낀 딜부터 채우고 남는 자리를 최근 M&A로 메운다
5. **자본시장 관련 보도**(절반 폭) — 딜 카드 바로 옆. 그룹 이름에 「자본시장」이
   든 기사를 최신순 다섯 줄. 공시는 확정된 사실이라 정확한 대신 늦고 기사는
   빠른 대신 「검토 중이라고 한다」까지라, 둘을 나란히 두면 「기사에는 났는데
   공시는 아직」인 건이 한눈에 보인다. 딜 화면의 관련 보도와 같은 `딜뉴스대상()`
   을 쓴다 — 두 자리가 다른 셈을 하면 반드시 어긋난다.
   이 짝만 `align-self:stretch` 로 높이를 맞춘다(`#tab-home` 은 `align-items:start`
   라 그냥 두면 짧은 쪽이 위로 붙어 어긋난다)
6. 그룹별 수집 현황 · 7. 실리코시스 요약 — 기본이 2열이라 넓은 화면에서 나란히 선다

카드 머리의 「전체 딜 →」·「전체 보도 →」는 `data-goto-deal` 로 딜 화면의 어느
하위 탭을 열지까지 들고 간다.

**카드 폭**도 설정이 정한다. `설정보이기()`가 `data-col`(1=한 줄 전체, 2=절반)을 찍고
CSS 는 `#tab-home > [data-col="2"]{grid-column:auto}` 하나로 처리한다. 2열 카드가
연달아 오면 그리드 자동 배치가 알아서 짝을 짓는다.

카드 안쪽 격자(`.hi` 지표 칸, `.co-grid` 계열사 카드)는 화면 폭이 아니라
`repeat(auto-fit, minmax(...))`로 **카드가 실제로 가진 폭**에 맞춘다. 화면 폭으로
칸 수를 정하면 절반 폭 카드에서 글자가 잘린다.

KPI 4개(마지막 수집 / 최근 7일 / 중요도 4↑ / 실리코시스 30일)는 **주요 뉴스 카드
머리(`.mail-head`) 안**, 「전체 기사 →」 왼쪽에 `.kpi-mini`로 작게 붙는다. 카드 안에
들어 있어서 순서 목록(`c.순서`)에는 넣지 않고 on/off만 따로 둔다(`CFG_KPI`). 이 때문에
`설정보이기()`의 재배치는 `:scope > [data-card=...]`로 직계 자식만 집는다 — 그냥
`querySelector`로 집으면 요약 숫자가 카드 밖으로 끌려 나온다.

`#tab-home`은 CSS 그리드다. `display:grid`를 `#tab-home.active`에만 거는 이유는
`.tab-panel{display:none}`보다 id 선택자가 세서, `#tab-home{display:grid}`로 두면 다른
탭에 있어도 첫 화면이 보이기 때문이다.

### 대시보드 설정

헤더의 「대시보드 설정」. localStorage(`lx-cfg`)에만 저장하며 서버로 전송하지 않는다.

- **첫 화면 구성** — 카드 6개를 체크로 on/off, ▲▼로 순서 변경, 「1열/2열」 버튼으로
  폭 변경 (`설정순서(통, 사전, 차례, 그릇, 폭그릇, 뒤에)` — `폭그릇`이 null 이면
  폭 버튼을 그리지 않는다. 계열사 하위 탭이 그 경우다)
- 요약 숫자 4개 on/off (`#cfgKpi`, 순서 변경 대상이 아님)
- 주요 뉴스 기준(중요도/관련성/긴급성)
- 주요 뉴스 표시 방식 — 먼저 펼칠 건수(기본 5), 최대 건수(기본 15),
  정렬(`score` 총점순 / `date` 최신순)
- **계열사 화면 구성** — 하위 탭 4개 on/off + 순서 변경. 맨 위 탭이 기본 진입 탭
- 표시할 계열사 on/off
- 기본값 복원 버튼

**저장 버튼은 없다.** 값이 바뀔 때마다 `설정저장()`이 곧바로 localStorage 에 쓴다.
대신 화면 아래에 붙는 `.cfg-bar`(sticky)에 마지막 저장 시각을 적는다. `설정저장()`은
`기억()`을 쓰지 않고 `localStorage.setItem`을 직접 호출한다 — `기억()`이 실패를
삼켜서 성공 여부를 알 수 없기 때문이다. 실패하면(시크릿 모드 등) 띠가 붉게 바뀌며
창을 닫으면 설정이 사라진다고 알린다.

저장 형태:
```
{ 순서:['ind','mail','co','deal','groups','risk'], home:{...,kpi},
  폭:{mail:1,co:1,ind:1,deal:1,groups:2,risk:2},
  판:2, 하위순서:['group','index','comp','risk'], sub:{...}, 계열사:{...},
  기준:{중요도,관련성,긴급성,손댐,읽었나}, 뉴스수:15, 첫뉴스수:5, 정렬:'score' }
```
`순서맞추기()`가 저장된 배열에서 모르는 이름을 버리고 빠진 것을 기본 순서대로 뒤에
붙인다. `폭맞추기()`는 1도 2도 아닌 값을 기본으로 되돌린다.

**`CFG_판`**: 기본 차례를 바꿔도 이미 쓰던 사람의 저장값이 이기므로 새 기본값이 닿지
않는다. 판을 올리면 `판올리기()`가 저장된 `하위순서`와 `lx-co-sub`만 한 번 버린다.
`coSub`가 스크립트 위쪽에서 곧바로 정해지므로 `설정()` 안이 아니라 그보다 앞에서 돈다.
카드 순서·폭·뉴스 기준은 사람이 정한 것이라 건드리지 않는다. 둘 다 있어서 카드를
새로 넣거나 없앤 뒤에도 옛 설정이 그대로 동작한다.

**카드를 새로 넣는 법**: ① `#tab-home` 안에 `data-card="키"`를 단 `<section class="card">`
추가 ② `CFG_HOME`에 한 줄 ③ `CFG_기본.순서`·`CFG_기본.home`·`CFG_기본.폭`에 그 키 추가
④ `renderHome()`에서 그리는 함수 호출. 저장돼 있던 옛 설정에는 없는 키라 순서 맨 뒤에
기본 폭으로 붙는다.

기준값은 신청/변경 화면을 한 번 열면 그 계정 설정을 가져다 쓴다. 사용자가 설정에서
직접 조정하면 그 뒤로는 덮어쓰지 않는다(`기준.손댐` 플래그).

이걸 모르고 지표조회에 시트 읽기 노드를 추가했다가, 상위 노드의 2,000개 아이템마다

→ 노드 추가 후 반드시 `setNodeSettings`로 `executeOnce`를 지정하고,

| 운임 유럽향 | **추가** `FRT_EUR` | KCCI `KNEI` (주간, $/FEU) |
| MMA 국제가 $/t | 이미 있음(근사) | 관세청 MMA 수출·수입단가 (월별) |

- **ICI4/ICI5**(Coalindo·Argus), **SCFI**(상하이해운거래소), **MMA 스팟**(ICIS·Argus)은
  모두 유료 구독이라 무료·공신력 있는 대체가 없다. 뉴캐슬탄은 발열량이 달라
  ICI 대신이 아니라 방향 참고용이고, 지표 설명에도 그렇게 적어 두었다.
- **KCCI**는 부산 기점 13개 항로라 SCFI(상하이 기점)보다 우리 항로에 가깝다.
  주소에 `sDay`·`eDay`를 붙이지 않으면 최근 7일치만 오므로 2022-01-01부터 받는다.
  2022-11-07 이후 191주가 한 번에 들어온다. 페이지에 `(단위 : pt, $/FEU)`로 적혀 있다.
- 값은 `시장지표값` 시트에 `주기='일'`로 쌓는다. 조회 웹훅이 `'일'`만 일별 통에
  넣기 때문이다(`'주'`로 쌓으면 월별로 흘러가 미완성 달 규칙에 걸린다).
- 공통 지표가 8개에서 11개가 되어 첫 화면 공통 카드 상한을 8 → 12로 올렸다.

### 대시보드 구성을 다시 짰다 (2026-09-08)

메뉴 이름과 화면 구성을 사용자 요청대로 바꿨다. 모두 `hub.html` 안의 일이고
n8n 쪽은 손대지 않았다.

**① 이름** — 종합 상황판 → **Home**, 전체 기사 조회 → **키워드 뉴스**,
자본시장 딜 → **자본시장 딜 현황**. 나머지 둘은 그대로다.

**② Home** — 공통 지표를 유사한 것끼리 묶고(`HOME_IND`: 환율 / 기준금리 /
국채 3년 / 유가) 주요 지표만 남겼다. 자본시장 딜 카드는 최근 7일 등록분만 센다.

**③ 계열사 현황** — 하위 탭 줄(`#coSub`)을 없애고 **오른쪽 세로 계열사 줄**
(`#coTabs`, `.co-rail`)로 바꿨다. 「그룹 전체」를 고르면 그룹 실적만, 계열사를
고르면 경쟁사 성과와 리스크 관리가 함께 선다. 시장 지표는 **왼쪽 메뉴의 별도
항목**(`#tab-index`)으로 나갔고 계열사 줄(`#indTabs`)을 따로 그리되 `coTab`을
공유한다. 실적 보기는 매출액·영업이익 둘만(믹스·이익률 삭제), 기간은 연도별·
분기별 둘만 남겼다. 누계로 신고하는 회사(`분기꼴 === '누계'`)는 `comp분기로()`가
같은 해 앞 분기를 빼서 진짜 분기값으로 만든다.

  조금씩 어긋나고, 어긋난 뒤에는 어느 쪽이 맞는지 알 수 없다.

  박혀 있으면 그 점이 무슨 뜻인지 묻게 되고, 커서를 올렸을 때 생기는 점과
  헷갈린다. 점은 「지금 가리키는 곳」이라는 뜻 하나만 가진다.

### A. 계열사별 리스크 등록 (보류 중 — 사용자 결정 대기)

사용자가 테마를 지정했고, 키워드 초안까지 만들었으나 **아무것도 반영하지 않은 상태**다.

| 글라스 | 중국·인도산 반덤핑 |

| 하우시스 | 실리코시스 (현행 유지) |

**핵심 제약**: 리스크 탭은 수집 그룹이 있어야 동작한다. 실리코시스가 308건인 이유는
`해외_주요이슈` 전용 수집 그룹이 있기 때문이다. 위 5개 테마를 현재 코퍼스(2,506건)에
대고 측정하면 1~4건이고 대부분 오탐이다.

따라서 리스크 하나당 두 가지가 필요하다:
1. 신청/변경 화면에 **수집 그룹** 추가 (키워드 문법: `+` 필수포함, `-` 제외)
2. `리스크` 시트에 **한 줄** 추가 (그룹명 + 고유 단어 몇 개)

**미결 사항**: 수집 그룹을 만들면 그 기사가 팀 메일·텔레그램에도 발송된다.
현재 하루 139건 수집 → 98건이 기준 통과해 메일에 실린다. 선택지는
(a) AI 평가 켬 = 점수가 붙어 리스크 화면이 온전히 동작, 메일도 늘어남
(b) AI 평가 끔 = 메일 그대로, 리스크 화면에 중요도·별점 없음
(c) 인터·판토스만 먼저 1주일 시험 ← 권장
사용자가 "일단 아무것도 반영하지 마"라고 지시해 대기 중이다.

키워드 초안은 세션 대화에 있으며, 설계 원칙은 다음과 같다:
- 짧은 토막 금지. `DDI`는 `BuildDirect` 안에 부분 일치해 걸린다. `MMA`는 격투기·
  공시를 물어온다. `증설` 단독은 데이터센터 기사를 대량으로 끌어온다.
- 두 단어 이상의 고유한 표현을 쓴다(`산림 훼손`, `해상운임`, `상계관세`).
- 모호한 기준어는 `+`로 묶는다(`인도네시아+니켈`). `인도네시아` 단독은 판토스
  인도네시아 CSR 기사 7건이 걸렸다.

   `답 만들기` 부문 필터가 그것을 쓰레기로 보고 버렸다. 뒤에 `전사 보태기` 노드를
   붙여, 부문이 하나도 안 잡힌 회사만 「전사」 한 줄로 되살린다. 이것으로
   **LX세미콘·LX MMA**가 살아났고 경쟁사 쪽에서도 8곳(현대글로비스·SK네트웍스·
   아나패스·금호석유화학·대한유화·이건창호 등)이 함께 살아났다.

2. **LX판토스·LX글라스는 숫자 자체가 없었다 (고침)** — 진단해 보니 원인은 하나였다.
   두 회사의 요약 손익표는 과목을 **「I. 매출액」·「V. 영업이익」**으로 적는데,
   `부문 실적 뽑기`의 이름 읽기가 이름이 딱 「매출액」일 때만 알아본다. 그래서
   요약 손익 되돌림이 그 표를 통째로 지나쳤다. 연도(`제 48(당)기`)와 원 단위는
   기존 코드가 이미 다룰 줄 알았다 — 표를 못 읽으니 거기까지 가지 못했을 뿐이다.

   **고친 방법**: `부문 실적 뽑기`는 건드리지 않고, 뒤에 `요약 손익 되줍기` 노드를
   새로 붙였다. 앞 노드가 「부문표 못 찾음」 표시줄만 낸 보고서에서만 돌고, 그때
   과목 앞머리 번호(`I.` `V.` `1)`)를 떼고 다시 읽는다. 이름 읽기를 앞 노드에서
   느슨하게 바꾸지 않은 까닭은 그 함수가 **부문표 판정에도 쓰여서**, 느슨해지면
   이미 숫자가 잘 나오는 스무 회사에서 엉뚱한 표가 부문표로 잡힐 수 있기 때문이다.
   못 주우면 받은 표시줄을 그대로 흘려보낸다.

   후보표를 고를 때 **「종속기업」은 제외어에 넣지 않았다** — 연결재무제표 머리글이
   늘 「…와 그 종속기업」이라, 넣으면 정작 봐야 할 연결손익계산서가 통째로 빠진다
   (실제로 처음에 그 실수로 판토스가 안 나왔다).

   **결과**(라이브 확인): LX판토스 2021 7.82조 / 2022 10.67조 / 2023 6.88조 /
   2024 8.06조, 영업이익 3,604억 / 3,745억 / 1,560억 / 2,219억.
   LX글라스 2024 3,838억(영업이익 24억) / 2025 3,146억(영업이익 -345억).
   케이씨씨글라스처럼 부문표가 있는 회사는 되줍기가 열리지도 않는다 — 부문 이름이
   열 머리글이라 기(期)를 못 찾고 조용히 지나간다(그대로가 맞다).

   **되읽히게 만든 방법**: 추출기는 「경쟁사실적」에 이미 있는 접수번호를 다시 읽지
   않는다. 그래서 두 회사의 표시줄 10개의 `접수번호`를 비우고 `단위`에
   `되읽기 대기 (원래 접수번호)`를 남겼다(`TMP_판토스글라스_되읽기표시`). 줄을 지우지
   않은 까닭은 지우면 아래 줄 번호가 밀려 다음 지우기가 엉뚱한 줄을 건드리기 때문이다.
   남은 표시줄은 부문이 `—`라 `답 만들기`가 알아서 버린다.

`LX홀딩스`는 시트에 `사용=FALSE`다(줄 2, 메모: "지주사 연결. 필요해지면 사용을
TRUE 로"). 켜면 그룹 실적에 지주사 연결 실적이 들어오는데, 자회사 매출을 다시 한 번
세는 셈이라 나란히 놓으면 오해를 부른다. **이것도 사용자 판단이 필요하다.**

하나를 보는 것이라 딜/경쟁사처럼 회사별로 값이 갈릴 이유가 없다.

화면(`tab-cal`)은 압축한 월 달력(요일 7칸 격자)과 그 아래 짧은 목록으로
이뤄진다. 날짜를 안 고르면 목록은 "다가오는 일정"(오늘 이후 최대 8건)을
보여주고, 날짜를 고르면 그 날짜의 일정만 보여준다 — 화면을 많이 차지하면
안 된다는 요구사항이라, 달력은 "몰려 있는 달"을 보는 용도로만 작게 두고
실제로 읽는 것은 목록 쪽에 맡겼다. 여러 날짜에 걸친 일정(예: 워크숍)은 그
기간의 날마다 표시되고 목록에서도 그 날짜를 클릭하면 걸린다.

달력 칸에는 점 대신 **일정 제목을 바로** 보여준다(한 칸에 일정이 여럿이면
"제목 외 N건"). 주말과 공휴일은 날짜 숫자를 빨강/파랑으로 색칠하고, 공휴일
칸에는 일정이 없어도 공휴일 이름을 표시한다. 공휴일 표는 양력 고정 공휴일
(신정·삼일절·어린이날·현충일·광복절·개천절·한글날·성탄절)과 음력·대체
공휴일을 분리했다 — 양력 고정 공휴일은 `KR_FIXED_HOLIDAYS`(월/일 8개)로
어느 해든 자동 계산되고, 설날·추석·부처님오신날(음력)과 대체공휴일은
`KR_LUNAR_HOLIDAYS`/`KR_SUBSTITUTE_HOLIDAYS`에 해마다 한 번 검증해 넣는
작은 표로 남긴다(현재 2026년분만 있음). 음력 변환과 대체공휴일 지정 규칙
(예: 현충일은 주말이어도 대체공휴일이 없음)은 자동 계산하면 틀릴 위험이 커서
일부러 자동화하지 않았다 — 표에 없는 해는 양력 고정 공휴일만 색이 붙고
음력·대체공휴일은 안 붙을 뿐, 달력 자체는 그대로 동작한다(제헌절은 국경일이지만
2008년부터 휴무일이 아니라 넣지 않음). **해가 바뀌면 `KR_LUNAR_HOLIDAYS`/
`KR_SUBSTITUTE_HOLIDAYS`만 다음 해분으로 채우면 된다.**

검증: iOS 캘린더의 실제 공개 캘린더 링크로 라이브 실행해 워크플로우가

실제로 시트→웹훅→화면까지 반영되는 것도 확인했다(합성 ICS 픽스처로도
종일/시간대 지정 이벤트, 매년 반복(YEARLY), 매월 n번째 요일 반복
(MONTHLY+BYDAY), COUNT 제한, EXDATE 제외를 전부 로컬에서 단위 검증한 뒤

   반대로 배정됐다. 순번(`무기간횟수`)은 표가 실제로 값을 뽑아낸 뒤에만

4. **자모 접두사 미제거** — 현대글로비스의 「(가) 매출액」처럼 앞에 붙는 자모

   추가.
5. **부문 이름 줄에 설명문이 끼임** — 현대글로비스 반기보고서는 부문 이름 줄

### `LXGroup_수집상태_점검` (`HKRcmGvzMcJ0kyCu`)

수집이 어디까지 됐는지 한 표로 보는 n8n 워크플로우다. **손으로만 돌린다**
(수동 트리거뿐이라 예약 실행이 없다). `경쟁사공시` 원장과 `경쟁사실적` 시트를
회사별로 대조해 이렇게 낸다:

| 칸 | 뜻 |
|---|---|
| `원장건수` | 원장에 있는 공시 수 |
| `저장안됨` | `처리`가 「저장」이 아닌 것 — 원문 내려받기가 걸린 건 (정정공시는 안 센다) |
| `실적남음` | 저장은 됐는데 아직 실적추출이 안 읽은 보고서 수 |
| `비용남음` | 같은 것을 비용추출 기준으로 센 수 (감사보고서는 안 세고, 판 재시도 규칙도 없다) |
| `실적줄` / `표시줄` | 실적 시트의 줄 수 / 그중 「부문표 못 찾음」 표시줄 |
| `실적연도` | 실제로 값이 있는 사업연도 목록 |

`실적남음 + 비용남음`이 큰 순으로 정렬한다. 첫 줄은 합계다. 시트를 고치지 않으므로
아무 때나 돌려도 된다. 표시줄 판정은 실적추출의 `판` 상수(지금 `v6`)와 같은 값을
쓴다 — 파서 판을 올리면 여기도 같이 올린다.

**밀린 것을 다 채우는 데 드는 실행 수** — 대기 건수를 배치 크기로 나누고, 마무리로
부문매핑마스터와 마스터정리를 한 번씩 더한다.

| 단계 | 한 번에 |
|---|---:|
| 원문저장 | 25 |
| 실적추출 | 20 |
| 비용추출 | 12 |
| 부문매핑마스터 · 마스터정리 | 전체 다시 쓰기라 각 1회 |

2026-09-08 에는 원문저장 2 · 실적추출 24 · 비용추출 5 로 여섯 번 계산이 나왔고
실제로 여섯 번에 끝났다. 그 뒤 파서를 v3로 올리면서 지난 실패분이 되살아나
실적추출 2회 · 비용추출 1회 · 마무리 2회를 더 돌렸다.

금요일 정기 실행이 이 워크플로우들을 각각 1회씩 돌리므로 **손대지 않아도 보통
2주면 채워진다.** 손으로 당길 때는 **`production` 모드로 돌린다** — `manual` 은
아이템을 전부 메모리에 물고 있어 큰 원문이 겹치면 `crashed` 로 죽는다.

대시보드 「↻ 업데이트」로 당기면 버튼 한 번이 `수동실행 + 공시수집 + 원문저장 +
실적추출` 4회다. 이 경로에는 비용추출·부문매핑·마스터정리가 없어 그 셋은 금요일을
기다린다.

## 그래프 표식·배색 통일 (2026-09-17)

시장지표 카드에만 있던 최고·최저·현재 표식(`indPlotMarked`)을 계열사 주요지표
(`indDraw`)와 실적현황·경쟁사현황(`compChart`)에도 적용했다. 숫자 옆에 작은
글자로 "최고"·"최저"·"현재"를 같이 적는다 — 전에는 숫자만 있어서 그것이 어느
값인지 표식과 색으로만 구분해야 했다.

- 한 점이 여러 뜻을 가지면("최고" 이면서 "현재") "최고·현재"로 묶어 한 번만
  적는다. 겹쳐 적으면 둘 다 못 읽는다.
- **선이 셋 이상이면 표식을 안 쓴다**(`indMarkable`/`indPlotAuto`). 선마다
  최고·최저·현재 셋을 찍으면 값이 비슷한 여러 경쟁사를 겹친 그래프에서 글자가
  서로 겹친다. 그 대신 기존 위아래 축 눈금(`ind-y hi/lo`)을 돌려준다 — 선이
  한둘일 때는 표식이 그 눈금 자리를 대신하므로 뺐다.
- 맨 왼쪽·맨 오른쪽 점은 글자를 가운데 정렬이 아니라 안쪽으로 붙인다. 카드를
  나란히 두는 자리(경쟁사 비교)에서 그림 밖으로 반쯤 삐져나온 글자가 옆 카드
  글자와 겹쳐 보이는 것을 막는다.
- **경쟁사·실적현황 배색(`COMP_색`)을 시장지표 배색(`IND_COLORS`)에서 맨 앞
  붉은색만 뺀 것으로 바꿨다.** 전에는 둘이 서로 다른 팔레트라 같은 회사가
  화면마다 다른 색으로 보였다. 붉은색은 적자·`COMP_우리편색`(우리 계열사 강조)
  전용이라 그대로 뺐다.

    임대료, 가전 판매량, 모바일생산량, LCD 출하량, 판유리 가동률·재고량 등.
    이건 리스크 탭이 아니라 지표마스터에 실제 수집원을 연결하는 일이고,
    대부분 아직 '신규 수집 필요' 상태다.
- **지금 도구로는 실제 운영 시트에 행을 못 넣는다.** Google Drive MCP는
  파일 단위 조작(만들기/휴지통/메타데이터)만 되고 스프레드시트의 특정 셀·행을

  지표마스터 탭에 새 행을 추가하는 작업은 n8n이 재인증된 뒤 그쪽에서 해야
  한다.

### 진행 항목 실연동 + 구글 드라이브 구조 정리 (2026-09-17)

사용자가 "진행하던 것 다 실제 대시보드 연결까지 구조화하고, 드라이브 구조도
효율화하고, 지표 카드에 수집주기·수집기간·출처·업데이트 기능을 넣고,
공시수집기에 회사별 업데이트 버튼과 기간선택(기존 기간 제외)을 넣어 달라"고
요청했다. 계획을 plan 파일(`splendid-kindling-lynx.md`)에 Phase 0(지금,
프런트만)/Phase 1(n8n 재인증 후, 백엔드)로 나눠 적어 뒀다. 이번에 Phase 0을
구현했다.

**구글 드라이브 `LX Group MI` 폴더 구조를 확인했다.**

```
LX Group MI/
├─ LX_Group_MI_Setting            운영 스프레드시트(여러 탭, API 키 포함)
├─ LX Group MI_관리항목 마스터(지표·리스크) v3   참고용 카탈로그
├─ 시장 지표/                      계열사별+공통 "OO 지표 마스터" 7개 시트
├─ 리스크 관리/{계열사}/            사건 원장류 파일(대부분 아직 빈 폴더)
├─ 경쟁사 분석/{계열사}/{회사명}/   DART 공시 원문(XML) — 이름은 "분석"이지만 실제로는 원문 보관소다
├─ 조사보고서/{날짜 제목}/          수시 심층조사 산출물
└─ 고객 폴더/                      LX_Group_기사후보 시트, DART 전체 회사코드

```

**정리안**: `경쟁사 분석` → `경쟁사 공시원문`으로 이름을 바꾸고, `고객 폴더`
안의 `DART_corpCode_전체목록.xml`(캐시)과 `LX_Group_기사후보`(내부 작업용
시트)는 새 `내부 자료/` 폴더로 옮긴다. **아직 실행하지 않았다.** 파일 ID는
이름·경로를 바꿔도 그대로라 n8n이 ID로 참조하는 한 안전하지만, 문자열
경로로 참조하는 노드가 있는지는 n8n을 열어야 확인할 수 있다(재인증 대기).
안전을 확인한 뒤에 실행한다(Phase 1-F).

**Phase 0에서 구현한 것 (hub.html)**

- **지표 카드마다 "출처 · 주기 · 수집기간 · 마지막 수집" 한 줄을 추가했다**
  (`indPeriodLabel()`). 새 서버 필드가 필요 없다 — 이미 그래프가 쓰고 있는
  시계열(`x.범위[기간].흐름`)의 첫 점·끝 점 날짜에서 그대로 구했다. 다만
  "수집주기"는 지금 `INDEX_URL` 응답에 그 필드 자체가 없어(지표마스터
  시트에는 `주기` 열이 있지만 응답에 안 실려 온다) **"확인 필요"라고
  그대로 적었다.** 실제 값을 보내려면 서버 조립 코드를 고쳐야 한다(Phase
  1-E).
- **「↻ 업데이트」 버튼에 범위 설명을 붙였다.** 이 버튼이 보내는 요청
  (`{code, pw, 대상}`)에는 지금 보고 있는 계열사가 안 실린다 — 그래서
  "이 계열사만"이 아니라 대상(지표/경쟁사) 전체를 다시 받는다고 안내한다.
  정확히 어느 시점부터 다시 받는지는 n8n 워크플로를 읽어야 알 수 있어
  **"아직 확인하지 못했다"고 그대로 적었다**(Phase 1-C에서 실제 로직을
  확인해 문구를 사실대로 바꾼다).
- **기업 관리 목록에 회사별 「업데이트 반영」 버튼을 추가했다.** 새
  컴포넌트를 만들지 않고, 이미 있는 공시수집기의 기간선택·저장 흐름
  (`discPickedCard`→`discResultCard`, `discPicked` 전역값)을 그 회사로 바로
  채워서 연다 — 회사 이름을 다시 검색할 필요가 없다. **"기존에 있던 기간은
  제외하고 검색"은 아직 못 넣었다.** 지금 `DB파일보유` 표시는 접수번호
  단독 매칭이라(경쟁사공시 중복 저장 정리 때 확인한 것과 같은 결함) 이
  신호를 그대로 써서 자동 제외를 만들면 정정본을 원본으로 착각해 거르는
  등 부정확한 필터가 된다. 정확한 자동 제외는 1-A(중복 판정 기준 수정)와
  같은 기준으로 만드는 저장현황 조회 API가 있어야 해서 Phase 1-B로 미뤘다.

**Phase 1(n8n 재인증 후)로 남긴 것**: 공시수집기 중복 저장 재발 방지(1-A),
회사별 저장현황 조회+기간 자동 제외(1-B), 업데이트 버튼 범위 문구를 실제
로직대로 확정(1-C), 관리항목관리 웹훅+리스크탭 실연동(1-D), 지표 카드
수집주기 서버 필드 추가(1-E), 드라이브 폴더 정리 실행(1-F). 전부
`splendid-kindling-lynx.md` 계획 파일에 상세가 있다.

### n8n 재인증 후: 「↻ 업데이트」 실제 동작 확인 + 관리항목 마스터를 시장지표에 반영 (2026-09-17 저녁)

n8n 커넥터가 `needs_reconnect` 상태였다가 사용자가 claude.ai에서 다시 연결해
`connected: true`로 바뀌었다. 재연결 직후에는 이 세션의 도구 목록에 바로 안
잡혔고, 몇 분 뒤 재확인하니 잡혔다 — **OAuth 재인증과 세션의 MCP 도구 로딩은
별개 단계이고 시차가 있을 수 있다.**

**「↻ 업데이트」 버튼이 정확히 무엇을 하는지 확인했다(Phase 1-C 완료).**
`RUN_URL` 뒤의 실제 워크플로는 `LXGroup_지표수집`이다.

- 소스는 ECOS·FRED·관세청(CUSTOMS)·KOSIS 넷뿐이다. USGS·MPOB·NAR·ECB·
  Eurostat·EIA·DART·민간 리서치는 이 워크플로가 아예 모른다.
- **지표마다 "처음 한 번은 전부, 그 뒤로는 최근 구간만" 받는다.** 시장지표값
  시트에 그 지표ID로 한 줄도 없으면 '최초'로 보고 전체 기간(ECOS 일별
  2010년부터, 월별 20년, FRED 2010년부터, 관세청 2018년부터, KOSIS
  2006년부터)을 받는다. 한 줄이라도 있으면 '보충'으로 보고 최근 구간만
  받는다(ECOS 일별 120일·월별 24개월, FRED 24개월, 관세청 최근 1~2년,
  KOSIS 24개월).
- 관세청은 발표가 늦어(전달치가 다음 달 15일경 나옴) 확정된 달까지만
  받는다. 매주 금요일 08:00에 자동으로 돌고, 대시보드 버튼도 같은
  워크플로를 부른다. **화면 캡션 문구를 이 내용으로 갱신했다**(향후 hub.html
  작업).

**관리항목 마스터(v3)를 실제 시장지표 탭에 반영했다(사용자 요청 "각 계열사별
주요 지표에 다 반영해").**

- 관세청 소스로 이미 수집 중인 단가 지표와 같은 HS 코드를 재사용할 수 있는
  물량 지표 6개(니켈·보크사이트·팜유·유연탄 수입량, 보크사이트 수입단가,
  판유리 수입량)를 실제 조회설정과 함께 `시장지표` 탭에 추가하고,
  `LXGroup_지표수집`을 수동 실행해 즉시 수집을 시작시켰다.
- **결함을 하나 발견했다.** 니켈·팜유·판유리 수입량 3개는 관세청 API 응답
  자체는 정상(진단용 워크플로로 직접 확인, resultCode 00)인데 값이 하나도
  안 쌓였다. 원인은 `LXGroup_지표수집`의 `값 정리하기` 코드가 관세청 응답을
  지표에 **배열 순서(위치)로만** 짝짓고 있어서(ECOS는 응답 안의
  statCode·item1로 다시 확인하는데 관세청은 그런 재확인이 없다), 같은
  HS 코드를 쓰는 지표가 두 개 이상이면(예: 니켈 수입량과 니켈 수입단가가
  둘 다 hsCode 7502) 순서가 섞이는 것으로 보인다. **이미 도는 44개 지표에
  영향을 줄 위험이 있어 이번에는 코드를 고치지 않았다.** 대신 이 3개는
  `사용`을 꺼서 매주 조용히 재시도만 하고 영원히 값이 안 쌓이는 상태를
  막았다. 고치는 방법은 ECOS처럼 응답 안의 식별자(hsCode·flow)로 재확인하는
  것이다 — 마스터 파일의 "다음에 할 일"에 적어 뒀다.
- 자동 수집 소스가 아예 없는 나머지 14개(항공운임·물류창고 임대료·
  미국/유럽 주택 통계·가전 판매량·모바일생산량·LCD 출하량·판유리
  가동률/재고량·원판유리 생산량·MTBE 생산량)는 `시장지표` 탭에 `사용=TRUE`로만
  등록했다. `LXGroup_지표조회` 코드를 확인한 결과, 값이 하나도 없는 등록
  항목은 화면의 "아직 값이 없는 지표" 목록에 그대로 뜬다(기존에 이미 있는
  메커니즘이라 새로 만들 필요가 없었다).
- **새 파일**: `LX Group MI_관리항목 마스터(지표·리스크) v4`
  (`1iQAJSWm-8LXRBRGgqmK41_Eoebf0IO2xYHNu2vsyvqk`). v3
  (`1uAyScGRJA9_eOXEKz6_0yzwBS4DVlfaIciL-b1ua0F4`)는 휴지통으로 옮겼다. v3에서
  실수로 만든 중복 행(IND-069·IND-070, 이미 IND-049·IND-023과 같은
  지표ID를 가리킴)도 이번에 지웠다.
- **작업에 쓴 일회성 n8n 워크플로 4개**(`LXGroup_지표_신규등록`,

- **아직 안 한 것**: IND-038(공동주택 인허가)은 착공실적(KR_HOUSE_START)과

  `lxgroup-관리항목관리` 웹훅도 여전히 없다.

### 사건 추적형 리스크를 키워드 뉴스 그룹에서 바로 등록하게 함 (2026-09-17)

관리항목 마스터의 사건 추적형 리스크 3개(IND-066 USMCA 정책동향, IND-067
반덤핑 관세현황, IND-068 인도네시아 동향)는 수치가 아니라 뉴스로 추적하는
항목이다. 이런 항목을 리스크 탭에 반영하려면 지금까지는 사람이 리스크 탭에
직접 새 행을 넣어야 했다. 이번에 키워드 뉴스 그룹(신청/변경 탭) 기능에서
바로 리스크로 등록할 수 있게 만들었다.

- **hub.html**: 그룹 추가 폼에 `⚠️ 리스크로도 등록` 토글을 추가했다. 켜고
  관련 계열사를 하나 이상 고르면, `collectGroups()`가 그룹 객체에
  `risk: true`를 실어 보낸다.
- **저장 쪽(`lxgroup-intake`)은 건드리지 않았다.** `LXGroup_신청접수`의
  `설정행조립` 코드가 그룹 객체를 스키마 검사 없이 그대로
  `JSON.stringify`해서 `그룹키워드JSON` 칸에 저장하기 때문에, 새 필드
  (`risk`)를 추가해도 이 121개 노드짜리 거대 워크플로를 열 필요가 없었다.
  이 워크플로의 다른 11개 웹훅(공시 조회, 즉시 검색, 피드백 등)에 영향을
  줄 위험을 아예 피한 것이다.
- **합치는 쪽은 `LXGroup_지표조회`(`지표` 요청을 받아 지표·리스크를 한 번에
  응답하는 소형 워크플로)의 `지표 정리하기` 코드 노드에 추가했다.** 설정
  탭에서 그 계열사의 `그룹키워드JSON`을 파싱해, `risk===true`인 그룹마다
  고른 계열사 수만큼 리스크 항목(`{계열사, 이름, 키워드, 설명,
  사건원장: false}`)을 만들어 기존 `리스크` 탭에서 읽은 목록에 이어붙인다.
  그룹 JSON이 깨져 있어도 `try/catch`로 감싸 지표 조회 응답 자체는 그대로
  나가게 했다.
- **draft로 실제 계열사(LXHOLDINGS)에 수동 실행해 확인한 뒤 발행했다**
  (활성 버전 `1469b60b-a693-41e2-8add-71c327e6d6ad`). 지표 44개, 아직없음
  16개, 기존 리스크(실리코시스) 1건이 그대로 나오는 것을 확인했다 — 이
  시점에는 `risk:true`로 저장된 그룹이 실제로 없어서 그룹발 리스크 항목은
  아직 안 나왔다. Playwright로 그룹 폼에서 토글 클릭 → `collectGroups()`가
  `risk:true`를 담아 보내는 것까지는 확인했지만, **실제로 그런 그룹을
  저장해 화면 리스크 카드에 뜨는 것까지는 아직 확인하지 못했다.** 사용자가

## `비용저장` 429 오류로 이메일·텔레그램 발송이 통째로 막힌 문제 (2026-09-18)

2026-09-18 16:01 실행(`LXGroup_MI` 실행번호 7528, 하위 `LXGroup_MI_Sub`
실행번호 7529)이 `비용저장`에서 멈췄다는 텔레그램 실패 알림이 왔다. 오전
실행은 정상이었다.

**원인.** `비용저장`(Claude API 사용량을 시트 `API사용량`에 기록하는 노드)이
구글 시트 API의 `WriteRequestsPerMinutePerProject` 할당량(분당 8000건)에
걸려 429로 실패했다. 이 할당량은 `LXGroup_MI_Sub` 혼자 쓰는 것이 아니라
`공용 - Google Sheets` 자격증명이 속한 구글 클라우드 프로젝트 전체가
공유한다(회사의 다른 워크플로들과 같은 프로젝트다). 어제 고친 AI 평가
배치 나누기와는 무관하다 — 이 실행은 기사량이 25건을 안 넘어 배치가
원래대로 1개뿐이었다.

**실제 영향이 있었다.** 실행 기록을 확인해 보니 `AI 결과반영` →
`신규만저장` → `필터링된 기사 저장` → `기사후보저장` → `중요기사필터` →
`기사별메시지조립`까지는 전부 성공해서 기사 저장은 끝났는데, `이메일
발송`·`텔레그램 발송`·`발송동기화`는 실행 기록 자체가 없었다. `비용저장`은
이 발송 경로와 무관한 병렬 가지인데도, n8n은 노드 하나가 처리되지 않은
오류로 끝나면 그 실행 전체를 그 자리에서 멈춘다. 그래서 사용량 로그 한 줄을
못 남긴 대가로 그날 16시분 기사 발송 자체가 안 나갔다.

**고친 것.** `비용저장` 노드의 `onError`를 기본값(`stopWorkflow`)에서
`continueRegularOutput`으로 바꿨다. `비용저장`은 다운스트림 노드가 없는
로그 전용 노드라, 이 노드가 실패해도 나머지 흐름에 영향이 없다. 재시도도
3회·3초 간격에서 5회·5초 간격으로 늘려 일시적 할당량 초과를 좀 더 버티게
했다.

**확인한 방법.** `실패할것`이라는 노드가 무조건 오류를 던지도록 만든 별도
임시 워크플로(`LXGroup_임시_onError검증`)로 n8n 엔진의 동작 자체를
확인했다. `onError` 기본값에서는 실패한 노드와 전혀 무관한 병렬 가지의
노드(`정상실행`)가 실행 기록조차 안 남았고, `onError: continueRegularOutput`
으로 바꾸자 같은 병렬 가지가 정상적으로 끝까지 실행됐다. `비용저장` 자체를
실제로 429로 실패시켜 보지는 않았다(공용 할당량을 일부러 더 쓰는 것이라
피했다) — 노드 하나가 실패로 끝나는 상황에서 나머지 흐름이 어떻게 되는지는
어떤 이유로 실패하든 n8n 엔진 입장에서 같으므로, 이 검증으로 충분하다고
판단했다. draft에서 확인한 뒤 발행했다(활성 버전
`f1762930-479a-4bd6-ab2c-1d281b805f0d`).

**아직 확인 못 한 것.** 다음 07·11·16시 실행에서 `비용저장`이 다시 429로
실패해도 이메일·텔레그램이 정상적으로 나가는지는 실제로 지켜봐야 한다.
공유 할당량 자체를 줄이는 것은 이 저장소 밖의 일이라(회사의 다른 워크플로
트래픽) 손댈 수 없다.

않는다고 해서, `비용기록`(Code, 로그 한 줄 조립)과 `비용저장`(Sheets 기록)
두 노드를 비활성화했다. 둘 다 `Claude API 호출`에서 갈라진 자기 완결
가지고 다운스트림이 없어서, 꺼도 이메일·텔레그램 발송 등 나머지 흐름에는
영향이 없다. 위의 `onError` 수정은 그대로 남겨 뒀다 — 나중에 이 로그를
다시 켜거나 비슷한 로그용 가지를 새로 만들 때 같은 문제가 재발하지 않게
하기 위해서다. draft에서 확인 후 발행했다(활성 버전
`4805117a-246f-4831-a25f-9f2cfa356ef3`).

## 계열사·경쟁사 실적 반영 밀림 확인, 회사별 「최신 공시 반영」 버튼 신설 (2026-09-21~22)

**계기.** 사용자가 공시수집기로 일부 회사의 공시를 드라이브에 저장했는데
대시보드 실적 화면에 반영이 안 됐다고 확인 요청했다.

**원인.** DART 원문 저장(`처리=저장`)까지는 됐지만, 그 원문에서 실적 숫자를
뽑아 대시보드가 읽는 `경쟁사실적` 시트에 쌓는 단계(`LXGroup_경쟁사_실적추출`,
주 1회 금요일 새벽 자동 실행, 회당 20건 처리)가 아직 안 돈 상태였다.
LX홀딩스·LX세미콘·LX하우시스·케이씨씨글라스 네 회사에 걸쳐 원문 40건이
밀려 있었다. `LXGroup_수집상태_점검`(손으로만 돌리는 대조용 워크플로)으로
확인했다. 그 자리에서 `LXGroup_경쟁사_실적추출`을 두 번, `LXGroup_경쟁사_비용추출`을
두 번 수동 실행해 밀린 것을 전부 처리했다. LX홀딩스는 `경쟁사` 시트에
`사용=FALSE`(설명: "지주사 연결. 필요해지면 사용을 TRUE 로")로 이미 꺼져
있어서 대시보드 경쟁사 비교 화면에는 원래부터 안 나온다 — 이번에 건드리지
않았다.

**다시 밀리지 않도록 회사별 버튼을 새로 만들었다.** 이제까지는 밀렸는지
확인하려면 `LXGroup_수집상태_점검`을 손으로 돌려야 했고, 반영하려면 실적추출을
수동으로 여러 번 돌려야 했다. 대시보드의 경쟁사 현황·실적 현황·그룹 실적
블록마다(`compBlock()`이 그리는 회사 하나짜리 블록) 「🔄 최신 공시 반영」
버튼을 달았다. 누르면 새 웹훅 `LXGroup_실적반영`(경로 `lxgroup-실적반영`)이
그 회사의 corp_code로 공시수집기의 `공시검색`을 불러 아직 저장 안 된 것만
골라 `db저장`을 순서대로 부르고, 끝나면 그 회사만 상한 없이 처리하는
`LXGroup_경쟁사_실적추출`을 곧바로 부른다. 응답은 202로 먼저 보내고 뒤에서
계속 돈다(`LXGroup_수동실행`과 같은 방식). 화면은 120초 뒤에 자동으로 다시
불러온다.

- `LXGroup_경쟁사_실적추출`의 `읽을 보고서 고르기` 노드에 `회사명필터`를
  추가했다. `손으로 부를 때` 트리거 입력에 이 필드가 실려 오면 그 회사분은
  주간 배치 상한 20건 없이 전부 처리한다. 필터가 없는 기존 경로(주 1회
  스케줄, 대시보드의 「전체 갱신」 버튼)는 그대로다. 가짜 원장 데이터로
  Node.js 단위 테스트를 돌려 필터 있음·없음 두 경로가 각각 기존 그대로인지,
  필터가 실제로 그 회사만 상한 없이 골라내는지 확인했다.
- `LXGroup_실적반영`은 요청에 실행 비밀번호(pw)를 그대로 들고 다니므로
  `비용저장`과 같은 이유로 성공·실패 실행 데이터를 저장하지 않는다
  (`saveDataSuccessExecution`/`saveDataErrorExecution`: `none`).
- 실제 웹훅을 draft에서 틀린 비밀번호로 호출해 인증 실패 응답(401,
  `{ok:false,error:'auth'}`)을 확인했다. 성공 경로는 실제 실행 비밀번호가
  필요해 이 세션에서 직접 실행하지 않았다 — 화면에서 실제로 눌러 확인하는
  쪽이 안전하다.
- 화면 쪽은 Playwright로 데스크톱(1200px)·모바일(390px) 둘 다 확인했다.
  버튼이 경쟁사(우리편 아님)와 우리 계열사 블록 양쪽에 다 뜨고, 눌렀을 때
  올바른 corp_code·회사명으로 웹훅을 부르는 것까지 확인했다.

**아직 확인 못 한 것.** 사용자가 실제로 버튼을 눌러 밀린 공시가 끝까지
저장·반영되는 것은 이 세션에서 실제 비밀번호로 확인하지 못했다. 처음 몇 번은
결과를 지켜봐야 한다.

**기존 상단 「↻ 업데이트」 버튼 제거(2026-09-22).** 경쟁사 현황·실적 현황·
그룹 실적 화면 맨 위에 있던 전체 재수집 버튼 세 개를 없앴다. 회사 하나만
밀렸어도 관계없는 회사까지 다시 받고 주간 배치 20건 상한에 걸릴 수 있었는데,
회사 블록별 「최신 공시 반영」 버튼이 그 회사만 정확히 처리하므로 더 쓸

경쟁사 항목을 지우고 관련 주석을 갱신했다. main에 반영했다.

## 그래프 항목별 보이기·숨기기 체크박스 (2026-09-22)

**요청.** 시장 지표·경쟁사 현황·실적 현황처럼 항목이 여럿인 그래프에서,
목록 줄마다 체크박스를 달아 그 선을 그래프에서 뺐다 보일 수 있게 해 달라고
했다.

**구현.** `indBlock`(시장 지표), `compBlock`(계열사 하나의 부문별),
`compVsOursBlock`(경쟁사 대비 전사 비교), `compGroupBlock`(계열사끼리 전사
비교) 네 곳 전부에 달았다 — 이 넷이 목록(범례)과 그래프를 같이 그리는
자리다. 항목이 둘 이상인 블록에만 체크박스가 뜬다. 하나뿐인 지표에는 뺄
대상이 없다.

- 상태는 `그래프숨김`(블록 열쇠 + 항목 이름을 키로 쓰는 객체) 하나로 넷이
  같이 쓴다. 기본은 전부 보임 — 숨긴 것만 기억한다.
- 체크를 꺼도 **목록에는 그대로 남는다.** 숫자·증감은 계속 보이고, 그래프·
  표(펼쳐 둔 경우)에서만 그 선이 빠진다. 선을 없앤 것이 아니라 잠깐 가린
  것이라는 뜻을 살리려는 것이다.
- 전부 꺼서 그릴 선이 없으면 "체크박스를 전부 꺼서 그릴 선이 없습니다"
  (시장 지표) 또는 기존 "이 기간에는 견줄 만한 자료가 아직 없습니다"
  (경쟁사·실적, 이미 있던 빈 상태 문구를 그대로 재사용) 문구가 뜬다.
- 체크박스 처리는 각 화면이 이미 갖고 있던 델리게이트 클릭 핸들러
  (`comp누름`, `indBody`/`indCommonBody`의 클릭 핸들러)에 얹었다. 체크박스를
  눌러도 그 값을 바로 반영해 다시 그린다 — 다른 버튼(기간·통화·그래프 펼침)과
  같은 재그리기 경로다.

**확인한 방법.** Playwright로 로컬에 띄워 확인했다. `compVsOursBlock`에서
체크박스 3개가 뜨고, 하나를 끄면 그래프 선(`<path>`)이 3개에서 2개로
줄면서도 목록 항목은 3개 그대로인 것, 전부 끄면 선이 0개가 되고 안내
문구가 뜨는 것을 확인했다. `indBlock`도 같은 방식으로 선이 2개에서 1개로
주는 것을 확인했다(다만 이쪽은 실제 클릭이 아니라 상태를 프로그램으로
바꾸고 다시 그리는 방식으로 확인했다 — 지표 하위 탭 전환에 쓴 임시 코드가
실제 탭 전환 경로와 어긋나 클릭 자체가 보이지 않는 원소에 막혔다. 코드
경로는 compBlock 계열과 완전히 같아서 이 확인으로 충분하다고 판단했다).
데스크톱(1200px)·모바일(390px) 스크린숏으로 체크박스가 목록 줄과 겹치거나
넘치지 않는 것도 봤다.

## 시장 지표 목록을 한 줄 카드로 압축, 누르면 그 지표만의 그래프 펼침 (2026-09-22)

**요청.** 시장 지표는 계속 늘어나므로, 목록 줄마다 설명·기간·증감까지 다
펼쳐 두면 화면이 너무 길어진다. 제목과 현재값만 보이는 한 줄 카드로 줄이고,
줄을 누르면 그 지표의 상세와 그래프가 펼쳐지게 해 달라고 했다. 그룹 구조
(그룹 헤더, 여러 지표를 같이 보여주는 그래프, 기간·통화 선택, 그래프/표
버튼)는 그대로 두고, 그 안의 **지표 줄만** 압축하는 것으로 범위를 정했다.
펼쳤을 때 보여줄 것도 물었는데, 표가 아니라 **그 지표 하나만의 작은
그래프**로 정했다.

**구현.** `indBlock`(시장 지표 전용, `hub.html` `indBody`/`indCommonBody`)
안의 목록(`목록`) 렌더링만 고쳤다. 실적 현황·경쟁사 현황(`compBlock`,
`compGroupBlock`, `compVsOursBlock`)은 손대지 않았다 — 이번 요청은 시장
지표 한정이었고, 그쪽은 여전히 옛 `ind-leg`/`ind-leg-b`/`ind-leg-t` 구조
그대로다. 그래서 새 카드는 클래스 이름을 완전히 새로(`ind-item*`) 두어
기존 클래스와 안 겹치게 했다 — 겹쳤으면 CSS 하나 고칠 때마다 두 화면이
같이 흔들린다.

- 접힌 기본 상태: 색 표식 + 제목(줄임표로 한 줄) + 현재값만. 체크박스는
  기존 그래프 숨김 기능(2026-09-22 위 항목) 그대로 같은 자리에 남는다.
- 줄을 누르면(`지표펼침`, 블록 열쇠+지표 이름을 키로 쓰는 새 상태 객체)
  아래에 선행개월 배지·설명·출처/주기/수집기간·증감 배지·그 지표 하나만의
  작은 선 그래프가 펼쳐진다. 다시 누르면 접힌다.
- 지표 하나만의 그래프는 `indBuild([x], R, 스타일)`로 그 자리에서 만들어
  `indGraph[블록열쇠+'@'+지표이름]`에 담고, 그 열쇠를 `.ind-chart`의
  `data-g`에 적어 둔다. 커서 훑기(`그래프커서`)는 이미 `data-g` 있으면
  그것을 먼저 보게 짜여 있어서, 새 배선을 더 안 해도 마우스를 올리면 값
  상자가 그대로 뜬다. 값이 두 점이 안 되어 그래프를 못 그리면 "그래프를
  그릴 만큼 값이 쌓이지 않았습니다"라고 적는다.
- 펼친 줄만 제 그래프를 만든다. 접힌 줄까지 매번 만들면 지표가 쌓일수록
  한 번 그리는 값이 계속 늘어난다.
- 체크박스를 누르는 것과 줄을 눌러 펼치는 것은 서로 안 걸린다. 클릭
  핸들러에서 체크박스를 먼저 가로채 처리하고 곧바로 끝내므로, 체크박스를
  눌러도 펼침 상태는 그대로다.

**확인한 방법.** 이번에는 실제 클릭으로 확인했다. `#coPaneNav
button[data-copane="ind"]`로 주요 지표 하위 탭을 실제로 눌러 열고,
`.ind-item-row`를 실제로 클릭해 펼치고 접었다. (지난 체크박스 작업 때는
같은 자리에서 클릭이 안 먹혀 상태를 프로그램으로 바꾸는 방식을 썼는데,
이번에 하위 탭 버튼을 실제 지원 경로(`coPaneNav`의 `data-copane` 버튼)로
누르니 문제없이 됐다. 그때 막혔던 것은 화면 전환 경로가 아니라 그 확인용
임시 코드 쪽 문제였던 것으로 보인다.)

- 접힌 상태에서 목록 줄이 제목+현재값 둘만 보이는 것, 줄을 누르면
  선행개월 배지·설명·수집기간·증감·그래프가 다 뜨는 것, 그래프에 실제
  선(`<path>`)이 그려지고 커서를 올리면 값 상자(`.ind-tip`)가 뜨는 것을
  확인했다.
- 체크박스를 눌러도 펼침 상태가 안 풀리는 것, 같은 줄을 다시 누르면
  접히는 것도 확인했다.
- 회귀 확인: 그룹 전체 그래프 버튼(그래프/표)과 체크박스로 그룹 그래프의
  선을 빼는 기존 기능이 그대로 되는 것(2개 → 1개로 주는 것)을 다시
  확인했다. 경쟁사 현황(`compBody`) 쪽 목록도 옛 `ind-leg-b`/`ind-leg-t`
  구조가 그대로 쓰이는 것을 확인해, 이번 변경이 그쪽에 안 새어 나간 것을
  확인했다.
- 데스크톱(1200px)·모바일(390px) 둘 다 확인했다. 모바일에서 지표 이름을
  일부러 길게 넣어 봤는데 줄바꿈 없이 줄임표로 잘리고, 페이지 전체
  가로 스크롤은 생기지 않았다.

**아직 확인 못 한 것.** 실제 시트에 쌓인 지표 수가 많을 때(지금은 계열사당
많아야 열몇 개) 카드가 늘어난 화면을 실제로 보지 못했다. 지표가 훨씬 많이
쌓이면 다시 한번 봐야 한다.

## 사용자 제보 셋 확인·수정 (2026-09-22)

주인이 화면 캡처 세 장과 함께 세 가지를 물었다. 순서대로 확인했다.

**1) 보크사이트 수입단가 그래프가 튄다 — "분기 누계를 가져와서 그러냐".**
n8n `LXGroup_지표조회`를 직접 실행해 실제 값을 받아 봤다. 분기 누계는
아니고, 원인은 따로 있었다. 보크사이트는 매달 고르게 들여오지 않고 몇 달에
한 번 배로 들여온다. 그 사이 달에는 통관되는 물량이 정상月의 5~7%밖에 안
되는데(46,000톤 대 1,300~3,200톤), 그 소액 거래에 붙는 금액은 상대적으로
커서 단가(금액÷중량)가 80~90에서 375~415로 튄다. 2024-11, 2025-02, 2025-05,
2025-09, 2026-03, 2026-05 여섯 달이 이랬다. 다른 관세청 단가 지표 15개는
전부 정상이었다(중앙값 대비 2.5배를 넘는 달이 하나도 없음) — 보크사이트만의
문제다.

- `LXGroup_지표수집`의 `값 정리하기`를 고쳤다. 재기가 '단가'인 관세청
  지표는 그 해 중량들의 중앙값을 구해, 어느 달의 중량이 중앙값의 30% 아래면
  그 달 단가를 안 낸다. 중량 자체(재기=중량, 즉 보크사이트 수입량)는 안
  거른다 — 적게 들여온 것은 사실이라 그대로 쌓는다. 표본이 4개월이 안 되면
  중앙값이 불안정하므로 안 거른다.
- 로직만 떼어 Node로 단위 시험했다(정상 지표는 그대로, 보크사이트류는 저물량
  달만 빠짐, 재기=중량은 안 걸림, 표본 부족 해는 안 걸림 넷 다 확인).
  이어서 draft를 실제로 실행해 오류 없이 도는 것도 확인했다(이번 실행은
  8월까지가 이미 확정 구간이라 새로 걸릴 달은 없었다 — 다음 달 관세청
  자료가 들어올 때부터 효과가 보인다).
- **이미 시트에 박힌 6줄은 고친 코드가 손대지 못한다**(`있음` 중복 방지가
  그 달을 이미 받은 것으로 본다). 그래서 일회성 워크플로를 하나 만들어
  `시장지표값` 시트에서 그 6줄만 확인 후 지우고, 실행을 마치고 archive
  했다. 지운 뒤 다시 실행해 0줄이 나오는 것으로 확인했다.

**2) 시장 지표 그래프에서 표식 글자가 겹친다.** `indPlotMarked`(최고·최저·
현재 표식)가 겹침을 '정확히 같은 칸'일 때만 막고 있었다. 최고점 바로 다음
칸이 현재값이면(화면에서 거의 붙어 보이지만 칸도 값도 다름) 둘 다 따로
찍혀 겹쳤다 — 캡처의 KCCI(컨테이너 운임) 카드가 이 경우였다. 픽셀 위치가
가까운 표식끼리는(가로 55px, 세로 55px 이내) 뒤에 놓이는 것을 한 단씩
세로로 밀어내게 고쳤다. Playwright로 그 모양(최고가 마지막 바로 앞 칸)을
그대로 재현해, 실제 렌더된 글자 상자끼리 겹치는 쌍이 0인 것을 확인했다.
기존 회귀(체크박스로 선 줄이기, 그룹 그래프 토글, 경쟁사현황 목록 구조)도
다시 확인해 안 깨진 것을 봤다.

**3) 「최신 공시 반영」 버튼이 오류가 뜬다.** 원인은 단순했다 —
`LXGroup_실적반영`(2026-09-21에 만든 워크플로)을 draft에서 인증 실패
경로만 확인하고 **publish를 안 했다.** `active: false`인 워크플로의
프로덕션 웹훅 주소는 응답이 없어서, 화면에는 "서버에 닿지 못했습니다"로
뜬다(fetch 자체가 실패한 것처럼 보인다). publish해서 `active: true`로
바꿨다. 이번 세션의 실수라 사용자 잘못이 아니다.

**커밋한 것.** `indPlotMarked` 수정만 hub.html에 있다(font/폰트 문제로
보였지만 실제로는 겹침 문제였다). 나머지 둘은 n8n 쪽 변경이라 코드
저장소에는 안 남는다.

## 계열사별 주요 공시, 기본값을 계열사만으로 바꿈 (2026-09-22)

주고 확인했다. 기본 상태에서 "전체2·정기보고서1·주요사항1", 목록 2건,
기간이 계열사 날짜 범위만 나왔다. 「경쟁사 공시 포함」을 누르니
"전체5·정기보고서3·주요사항2", 목록 5건, 기간도 넓어졌다. 모바일(390px)에서
체크박스 문구가 안 잘리고 가로 스크롤도 안 생기는 것을 확인했다.

## 계열사 주요 지표, 소속 자동 분류에서 사람이 고르는 방식으로 바꿈 (2026-09-22)

**요청.** 지금까지는 계열사별 주요 지표 탭이 `시장지표` 시트의 `소속`
컬럼(콤마로 구분한 계열사 이름)을 그대로 읽어 자동으로 걸러 보여줬다. 이
컬럼은 시트를 직접 열어야만 고칠 수 있었다. 요청은 두 가지였다. LX홀딩스
시장지표 탭이 (공통 태그가 붙은 것만이 아니라) 수집 중인 지표 전체를 다
보여줄 것, 그리고 계열사별 주요 지표 탭에서는 화면에서 바로 체크박스로
골라 그 계열사에 보일 지표를 사람이 하나씩 고르는 방식으로 바꿀 것.

**구현.** 기존 `소속` 컬럼을 없애지 않고 그대로 쓰되, 그것을 편집하는
화면을 새로 만들었다.

- **백엔드**: `LXGroup_지표소속관리`(webhook `lxgroup-지표소속관리`)를
  새로 만들었다. `code`·`pw`·`지표ID`·`계열사`·`포함`(불리언)을 받아
  비밀번호를 확인한 뒤(다른 반영 웹훅과 같은, 시간차 공격을 막는 상수시간
  비교 방식) `시장지표` 시트에서 그 지표 행을 찾아 `소속` 값에 계열사
  이름을 더하거나 뺀다. 지표를 못 찾으면 404, 인증 실패면 401을 응답하고
  성공하면 갱신된 소속 배열을 돌려준다.
- **프런트**: LX홀딩스 › 시장지표 탭은 이제 `공통` 태그와 무관하게 수집
  중인 지표 전체를 보여준다("지표 전체 · N개"). 안내문에 "계열사별 화면에
  보일 것은 그 계열사의 「지표 선택」에서 따로 고릅니다"라고 적었다.
  계열사별 › 주요 지표 탭에는 「지표 선택 열기」 버튼을 새로 넣었다. 열면
  전체 지표가 체크박스 목록으로 나열되고, 그 계열사 소속인 것만 미리
  체크돼 있다. 체크를 바꾸면 바로 `LXGroup_지표소속관리`를 호출해 반영하고,
  성공하면 그 계열사 카드 목록(`indBody`)을 다시 그린다. 비밀번호는 기존
  반영 버튼들과 같은 방식으로 세션에 저장해 재사용하고, 인증 실패 응답이
  오면 저장한 비밀번호를 지우고 체크 상태를 되돌린다.
- 아직 지표가 하나도 없는 계열사에는 "위 「지표 선택」을 열어 이 계열사에
  보일 지표를 체크하세요"라고 안내한다.

**확인한 방법.** n8n은 `prepare_workflow_pin_data`+`test_workflow`로 4가지
경우(추가/제거/지표못찾음/인증실패)를 전부 시뮬레이션 데이터로 확인한 뒤
발행했다 — 진짜 자격증명이나 운영 데이터는 건드리지 않았다. 프런트는
Playwright로 2026-09-22 12:11 `LXGroup_지표조회` 실행에서 받은 실제 지표
44개(소속 분포: 공통13·하우시스12·인터내셔널9·판토스7·글라스6·MMA3·
세미콘1)를 목으로 주고 여섯 가지를 확인했다. 시장지표 탭에 44개가 전부
나오는 것, 하우시스 지표 선택 목록에 44개가 나열되고 그중 12개(하우시스
소속)만 미리 체크된 것, 비밀번호 없이 체크하면 프롬프트가 뜨고 취소하면
체크가 원래대로 돌아가는 것, 비밀번호가 있을 때 체크하면 요청 바디가
정확하고(`{code, pw, 지표ID, 계열사, 포함}`) 성공 후 계열사 카드 항목 수가
12에서 13으로 느는 것, 인증 실패 응답을 받으면 체크가 되돌아가고 저장된
비밀번호가 지워지는 것, 모바일(390px)에서 선택 목록을 펼쳐도 가로 스크롤이
생기지 않는 것이다.

**아직 안 한 것.** 「공통 원본 내려받기」 버튼(`indCommonXlsBtn`)은
소속과 무관한 별개 기능(원본 출처 파일 다운로드)이라 그대로 뒀다.

## 지표 선택 체크박스, 인터내셔널만 뺄 수 없던 결함 (2026-09-23)

**제보.** "인터내셔널 기준으로 자원 단가, 수입량, 물동량 주요지표탭에 아직
들어가 있는데 체크 해제해서 뺄 수도 없다."

**원인.** `계열사` 짧은 이름과 `시장지표` 시트의 `소속` 글자가 다른
계열사가 하나 있었다. 다른 다섯 계열사(하우시스·글라스·세미콘·판토스·
MMA)는 짧은 이름과 시트의 소속 글자가 완전히 같은데, 인터내셔널만 짧은
이름이 `인터`이고 시트에는 `인터내셔널`로 적혀 있다. 카드를 고르는
`indTabItems`는 이걸 알고 앞머리(`인터`로 시작하는지)로 맞춰서 정상
표시했지만, 이번에 새로 만든 체크박스 목록(`지표선택그리기`)은 소속 배열에
`coTab`(`인터`)과 완전히 같은 글자가 있는지만 봐서 `인터내셔널`을 못
찾았다. 그래서 카드에는 뜨는데 체크박스는 꺼진 채로 나왔고, 눌러서 켜면
`인터`라는 새 글자가 하나 더 붙을 뿐 `인터내셔널`은 그대로 남아 빠지지
않았다.

- `지표선택그리기`가 `indTabItems`와 같은 판정 함수(`IND_TABS`의
  `맞나`)를 쓰도록 고쳤다. 체크박스마다 실제로 일치한 소속 글자를
  `data-match`에 담아 두고, 뺄 때는 그 글자를 그대로 서버로 보낸다(있는
  그대로의 글자를 지워야 실제로 빠진다). 아직 소속이 없어 새로 더할
  때는 일치하는 글자가 없으니 `coTab`을 쓴다 — 그래도 다음에 다시 그릴
  때 앞머리 판정으로 정상 인식된다.
- 다른 다섯 계열사는 짧은 이름과 소속 글자가 같아서 이 결함의 영향을
  안 받았다. 그래서 어제 확인(하우시스로 검증)에서는 못 잡았다.

**확인한 방법.** Playwright로 실제 지표 중 소속이 `['인터내셔널']`뿐인
「유연탄 수입단가」(COAL_PRICE)로 재현했다. 고치기 전에는 카드에는
보이는데 선택 목록 체크박스가 꺼진 채로 나오는 것을 그대로 재현해 확인한
뒤, 고친 코드로 다시 확인했다. 체크박스가 켜진 채로(`match: "인터내셔널"`)
나오는 것, 해제하면 요청 바디의 `계열사`가 정확히 `"인터내셔널"`이고 카드
목록에서 실제로 사라지는 것, 다시 체크하면 `계열사: "인터"`로 재추가되고
카드가 되돌아오는 것을 확인했다. 어제 만든 여섯 시나리오(하우시스 기준,
소속 글자가 짧은 이름과 같은 경우)도 다시 돌려 회귀가 없는 것을 봤다.

## 업데이트 관리 탭을 실적 관리로 바꾸고, 시장지표 항목과 조회 화면의 업데이트 버튼을 뺌 (2026-10-12)

업데이트 관리는 실적 관리로 바꾸고, 시장지표는 해당 내용에서 빼고, 지표

업데이트 버튼을 다 삭제하자."

**바꾼 것.** 전부 `public/lxgroup-mi/hub.html`이다.

- 탭 이름이 「🔄 업데이트 관리」에서 「🏢 실적 관리」로 바뀌었다. 내부
  식별자도 `updatemgmt`에서 `perfmgmt`로 바꿨다(`data-tab`, 패널 id,
  탭 전환 분기 세 곳).
- 실적 관리 탭에서 시장지표 카드(`updMgmtIndexChk`)와 그 실행 분기
  (`updMgmtRunOne`의 지표 갈래, `updMgmtRunLabel`)를 뺐다. 시장 지표
  업데이트는 지표 마스터 관리 탭의 「전체 업데이트」·「선택한 지표만
  업데이트」가 맡는다. 실적 관리의 실행 버튼은 「선택 회사 업데이트
  실행」이 됐고 회사마다 `lxgroup-실적반영` 웹훅만 호출한다.

  회사마다 「반영된 최근 공시 반기보고서 2026Q2」 같은 보조 줄을 적는다.

  공시를 「대략적인 기준」이라고 적는다.
- 실행이 끝나면 2분 뒤 `loadComp(true)`를 불러 보조 줄을 새로 적는다.
- 조회 화면의 회사 블록(`compBlock`)에 있던 「🔄 최신 공시 반영」 버튼과

  어디에도 실적 업데이트 버튼이 없다. 실적 업데이트는 실적 관리 탭에서만
  한다.

**확인한 방법.** Playwright로 기업목록·경쟁사 실적·실적반영 웹훅을 목으로
주고 확인했다. 탭 이름과 패널이 바뀐 것, 시장지표 체크박스가 없는 것,
계열사 1곳·경쟁사 2곳이 보조 줄과 함께 나오는 것(케이씨씨는 부문 둘 중 늦은
「분기보고서 2026Q1」을 고른다), 회사를 체크하고 실행하면 `lxgroup-실적반영`에
`{code, pw, corp_code, 회사명}`이 한 번 가는 것, 실적현황 탭에

**남은 것.** 공시수집기 탭의 `discTriggerCompRefresh`는 저장 뒤 실적 갱신을
`lxgroup-실행`(대상 '경쟁사')으로 부른다. 조회 화면의 버튼이 아니라 저장
절차의 일부라 그대로 뒀다.

## 경쟁사실적 파서 v12·v13, 분기=연간 잔존 오류와 LX홀딩스 연도 오류 수정 (2026-10-12)

**제보.** "남은 문제 확인 더해봐." LX인터내셔널의 분기 값이 연간 값으로
덮어써지던 결함(v11까지)을 고친 뒤에도 케이씨씨·벽산·현대코퍼레이션에
분기 매출액이 연간 매출액과 같은 행이 남아 있었다.

**원인.** 실제 공시 원문(케이씨씨 2023년 1분기, 현대코퍼레이션 2024년
반기)으로 재현했다. 전부 n8n `LXGroup_경쟁사_실적추출`의 코드 노드
「부문 실적 뽑기」다.

- 표 제목의 「제65기 1분기」와 「제65기」를 같은 기간으로 읽었다. 케이씨씨
  분기보고서는 네 표를 「제66기 1분기 / 제65기 1분기 / 제65기 / 제64기」로
  나란히 두는데, 연간 두 표가 분기 키로 묶여 하나는 버려지고 하나는 분기
  값인 것처럼 들어갔다.
- 「상반기」를 반기로 인식하지 못했다. 현대코퍼레이션은 「제49기 상반기」라고
  적어서 반기 누계가 그 해 연간으로 들어갔다.
- 종속회사 현황표를 빼려는 조건이 너무 넓었다. 앞글 어디에든 「종속회사」가
  있으면 표를 뺐는데, 케이씨씨는 부문표 바로 앞 문단에 「주요 종속회사로는
  …」가 있어 당분기 표가 빠졌고, 그러자 기수의 기준이 한 해 밀려 모든 해가
  하나씩 틀렸다.
- 부문 이름의 각주 번호(「기타(주1)」)를 떼지 않아 같은 부문이 둘로 갈렸다.
- 벽산의 의심 1건(정보통신업 2022Q2 0.1억 대 연간 0.1억)은 값이 거의 0이라
  같다고 판정된 것이다. 실제 오류가 아니다.

**고친 것(v12).** 제목의 분기·반기 글자를 가르고(`기읽기`), 「상반기」를
반기로 받고(`기헤더`), 종속회사 단어가 「부문」보다 표에 가까울 때만 빼고,
부문 이름의 각주 번호를 뗀다(`부문이름`). 「부문 거르기」는 각주 번호가
붙은 기간말(「전기말(주1)」)도 거른다. 판을 v12로 올려 전에 부문표를 못
찾던 보고서를 한 번 더 읽게 했다.

**한 번 더 찾은 것(v13).** 전체 검사에서 LX홀딩스에 사업연도 1953~1958년
행이 있었다. LX홀딩스 보고서는 자사 부문표(제2기~제5기)와 주요 종속회사인
LX인터내셔널의 부문표(제70기 이상)를 한 문서에 싣는데, 기수의 기준을
문서 전체의 가장 큰 기수로 잡아서 자사 부문이 68년 전으로 밀렸다. 이제
표마다 가장 큰 기수를 따로 세고, 전체 기준과 5 넘게 차이 나면 그 표의
기준을 쓴다(`표큰기수`, `기수기준`). 같은 회사의 표끼리는 많아야 두셋
차이라 전체 기준이 그대로 쓰인다. 실제 원문(2024년 사업보고서, 2025년
1분기보고서)으로 확인했다. 지주회사·교육및경영자문·벤처투자 부문이
2022~2025년으로 바르게 나온다.

**시트 정리.** 옛 파서로 들어간 행은 시트를 통째로 비우지 않고 회사별 행
구간만 지웠다(「TEMP 행삭제」, 아래쪽 구간부터 지워 행 번호가 밀리지 않게
했다). 케이씨씨·현대코퍼레이션 569행, LX홀딩스 300행을 지우고
`회사명필터`로 그 회사만 다시 추출했다. 지난번 시트 전체 비우기가 30분
멈추면서 운영 시트가 비어 있던 일이 있어 이 방식으로 바꿨다.

**확인한 결과.** 재추출 뒤 분기 매출액이 연간과 같은 행(연간 0은 제외)이
케이씨씨 0건(280행, 2018~2026), 현대코퍼레이션 0건(360행, 2018~2026),
LX홀딩스 0건(356행, 2019~2026, 2015년 이전 연도 0행)이다. 나머지 회사도
전부 0건이고, 벽산의 1건은 위에 적은 0 대 0 비교라 실제 오류가 아니다.

**남은 것.** 「부문표 못 찾음」 표시행이 회사마다 쌓여 있다(LX하우시스 52행,
현대글로비스 42행, CJ대한통운 33행). 판이 오를 때마다 다시 읽고 또
실패하면 표시행이 하나 더 붙는 구조라 생긴 것이다. 조회 쪽(답 만들기)은
이 행을 쓰지 않으므로 화면에는 영향이 없다. 지주회사업·경영컨설팅업·
신기술사업투자업처럼 LX홀딩스 분기보고서의 다른 표에서 온 부문이 같이
들어오는데, 전부터 있던 것이라 이번에는 손대지 않았다. 파서 코드는 n8n에만
있고 이 저장소에는 없다.

## 분기 실적이 누계로 그려지던 문제, 서버에서 석 달치로 바꿔 보냄 (2026-10-12)

**제보.** "현대글로비스 분기 실적은 누계 기준 아님? 각 분기의 실적이 들어가야
할 것 같은데. 문제라면 전체 기업 실적 다시 들여다봐."

**확인한 것.** 시트 `경쟁사실적` 전체(3,152행)를 읽어 회사·부문·해마다
분기 값의 모양을 재 봤다. 반기·3분기보고서의 부문표는 대개 연초부터의
누계를 싣는다. 2분기 ÷ 1분기가 2 가까이, 3분기 ÷ 2분기가 1.5 가까이 나오면
누계다. 결과는 세 갈래였다.

- 대부분 회사는 누계다(LX인터내셔널·케이씨씨·한진·현대코퍼레이션 등).
  이들은 `LXGroup_경쟁사_조회`의 「답 만들기」가 (분기 ÷ 연간)으로 누계라고
  판정했고 화면이 앞 분기를 빼서 그렸으므로 맞게 보였다.
- 현대글로비스는 부문별 연간 값이 시트에 없다(사업보고서에서 부문표를 못
  찾고 요약 손익의 전사 값만 있다). 그래서 판정이 비었고, 화면은 누계를
  분기별 그래프에 그대로 올렸다. 물류부문 2023년이 1분기 21,449억,
  2분기 44,031억, 3분기 66,472억으로 계단처럼 올라가던 것이 이것이다.
- CJ대한통운은 2021·2022년은 누계, 2023년부터는 석 달치다(보고서가 「3개월 |
  누적」 두 겹으로 바뀌어 추출기가 3개월 칸을 집는다). 한샘 기타, 현대코퍼레이션
  기타, 케이씨씨글라스 유리, LX홀딩스 지주회사도 해에 따라 모양이 다르다.
  회사마다 하나의 꼴로 정하는 방식으로는 한쪽 해가 틀린다.

**고친 것.** `LXGroup_경쟁사_조회`에 코드 노드 「분기 석달치로」를 「전사
보태기」 뒤에 더했다. 부문·해마다 세 근거(2분기÷1분기, 3분기÷2분기,
분기÷연간)로 누계인지 석 달치인지 판정하고, 누계면 앞 분기를 빼서 석 달치로
바꿔 보낸다. 근거가 없는 해(2분기 하나뿐이고 연간도 없을 때)는 같은 부문의
다른 해, 그다음 같은 회사의 다수결을 따른다. 그래도 모르면 손대지 않는다.
연간이 있으면 4분기를 연간에서 빼서 만들고 `계산: true`를 붙인다. 앞 분기가
없어 뺄 수 없는 누계 칸(2021년 2분기 등 84칸)은 버린다. 전에도 누계 회사는
화면이 같은 이유로 버리고 있었다. 이제 `분기꼴`은 '분기'(석 달치로 맞춤)
아니면 ''(못 가림)이고 화면은 받은 값을 그대로 그린다. 화면
(`comp분기로`)은 옛 판 서버가 '누계'를 보낼 때의 안전장치로 남겼다.

`hub.html`은 회사 블록 머리에 「4분기는 연간에서 1~3분기를 뺀 계산값」을
적는다. 분기별로 보고 있고 계산한 칸이 하나라도 있을 때만 적는다.

**확인한 방법.** 바꾸기 전 실제 응답(136개 부문)을 받아 새 노드 코드를
로컬에서 돌렸다. 869개 분기 칸 중 382개가 누계에서 석 달치로 바뀌었고 4분기
171개가 생겼다. 현대글로비스 물류부문 2023년이 21,449 / 22,582 / 22,441억으로
고르게 나온다. CJ대한통운 2023년 이후는 손대지 않았다. 같은 요청을 n8n 초안에
직접 실행해 136개 부문 전부 로컬 결과와 같은 것을 확인한 뒤 발행했다.
Playwright로 실제 응답을 목으로 주고 분기별 그래프와 머리말을 확인했다.

**남은 것.** 현대글로비스처럼 부문별 연간이 없으면 4분기를 만들 수 없다. 판정
기준(1.6배, 1.35배 등)은 이번 데이터에 맞춘 경험값이라 매출이 분기마다 크게
출렁이는 부문에서는 틀릴 수 있다. 벽산의 부문 이름 하나에 `&cr;`이 섞여 있다

## 지표 마스터 관리에 「한눈에 보기 묶음」 편집 추가 (2026-10-12)

**제보.** "시장지표의 한눈에 보기는 두 지표를 묶음 단위로 출력하는 경우가
기존에 있었는데, 그것도 직관적으로 조정 가능하도록 지표 마스터 관리에
기능 추가해."

**전에는.** 시트 `시장지표`의 `한눈에묶음` 글자가 같은 지표끼리 한 카드에
묶였다(기준금리는 한국·미국, 국채 3년은 한국·미국). 지표 마스터 관리에서는
지표 줄마다 그 글자를 손으로 적었다. 어느 지표가 어느 묶음에 있는지
한눈에 안 보였고, 글자가 한 자라도 다르면 다른 묶음이 됐다.

**바꾼 것(`hub.html`).**

- 지표 마스터 관리 맨 위에 「한눈에 보기 묶음」 카드를 뒀다
  (`indMgmt묶음그리기`). 상황판·시장지표 첫 카드와 같은 함수
  (`homeIndGroups`)로 묶으므로 거기 나오는 카드 그대로다. 카드마다
  이름 칸, 지표 칩, 「＋ 지표 넣기…」 고르기가 있다.
  - 칩의 ×: 이름이 있는 묶음에서는 그 지표를 묶음에서 빼 단독 카드로
    만든다. 단독 카드에서는 한눈에 보기 자체를 끈다.
  - 지표 넣기: 그 묶음에 없는 지표 전부가 후보다. 한눈에 보기가 꺼진
    지표를 고르면 켜면서 넣는다.
  - 이름 칸: 바꾸면 식구 전부에게 같은 이름을 보낸다. 단독 카드에 이름을
    적으면 묶음이 되어 다른 지표를 받을 수 있다. 이름을 지우면 식구가
    전부 단독 카드가 된다. 이미 있는 다른 묶음 이름을 적으면 그 묶음에
    합쳐진다.
- 지표 줄의 묶음 글자 칸을 고르기(`indmgmt-home-sel`)로 바꿨다. 단독 카드 /
  있는 묶음 이름들 / 새 묶음 만들기… 가운데 고른다. 새 묶음은 이름을
  물어서 보낸다. 한눈에 보기가 꺼진 지표에서 묶음을 고르면 켜면서 넣는다.
- 서버 호출은 전과 같은 `LXGroup_지표한눈에관리` 웹훅 하나다(`한눈에요청`,
  지표 하나에 요청 하나). 이름 바꾸기처럼 여러 지표를 바꿀 때는 차례로
  보내고 중간에 실패하면 거기서 멈추고 알린다(`indMgmt묶음바꾸기`). 성공
  뒤에는 상황판 첫 카드, 시장지표 첫 카드, 지표 마스터 관리를 다시 그린다.
  다시 그릴 때 「업데이트 대상」 체크는 유지한다.

**확인한 방법.** Playwright로 지표 10개(묶음 네 개, 단독 하나)를 목으로
주고 확인했다. 묶음 카드가 상황판과 같은 다섯 장으로 그려지는 것, 미국
기준금리를 ×로 빼면 단독 카드가 생기고 다시 「지표 넣기」로 돌아오는 것,
「국채 3년」을 「국채 단기」로 바꾸면 식구 둘에게 요청이 가는 것, 꺼진
지표를 지표 줄에서 「유가」로 고르면 켜지면서 들어가는 것, 「새 묶음
만들기…」가 이름을 물어 보내는 것, 요청 본문이 `{code, pw, 지표ID,
한눈에보기, 한눈에묶음}`인 것, 390px 폭이다.

## 지표 마스터 관리의 업데이트가 최신값을 안 가져오던 원인 (2026-10-12)

**제보.** "지표 마스터 관리에서 업데이트 요청해도 최신값이 안 들어온다."

**원인.** `LXGroup_수동실행`(rasNV9fNhONkZTOr)의 지표 분기가
「운임수집 부르기 → 지표수집 부르기」로 직렬 연결돼 있었다. n8n은 앞
노드가 0건을 내면 뒤 노드를 실행하지 않는다. 운임수집(KCCI)은 매주
월요일 한 번 새 값이 나오고 금요일 07:30 스케줄이 이미 받아 두므로,
화면에서 버튼을 누르는 날 대부분은 「새 값 고르기」가 0건으로 끝난다.
그러면 지표수집은 아예 불리지 않았다. 실행 기록으로 확인한 것은 이렇다.

- 운임수집의 수동 호출 실행(8580, 8430, 8302, 8298, 8284)이 전부
  「새 값 고르기」 0건에서 끝났다. 지표수집은 성공 실행을 저장하지 않는
  설정이라 직접 보이지 않지만, 같은 구조의 테스트 워크플로를 만들어
  하위 워크플로가 0건을 돌려주면 부모의 다음 노드가 실행되지 않는 것을
  재현했다(실행 8648).
- 10-12에 넣은 「선택한 지표만 업데이트」의 지표ID목록도 지표수집에 닿지
  않았다. 지표수집의 「손으로 부를 때」는 바로 앞 노드의 출력을 받는데,
  그것이 운임수집의 출력이지 요청 본문이 아니었다.
- 지표수집 자체는 정상이다. 손으로 실행(8450, 10-12 08:40)하면 최근
  구간을 받아 쌓는다.

**고친 것(n8n).** 「무엇을 돌릴까」의 지표 출력에서 운임수집 부르기와
지표수집 부르기를 나란히 부른다. 운임수집이 0건이어도 지표수집이 돌고,
지표수집은 요청 본문(`{대상, 지표ID목록}`)을 그대로 받아 선택한 지표만
거른다. 두 워크플로는 서로 다른 지표ID를 쌓으므로 순서가 바뀌어도 값이
섞이지 않는다. 운임수집 부르기 노드의 메모("지표수집보다 먼저")는 옛
설명이라 무시해도 된다.

경쟁사 분기(공시수집 → 원문저장 → 실적추출 → 회사공시수집)도 같은
구조였다. 공시수집의 「새 공시만 고르기」와 원문저장의 「받을 것 고르기」가
새 것이 없으면 0건을 내므로, 새 공시가 없는 날은 실적추출과
회사공시수집이 돌지 않았다. 세 노드(공시수집·원문저장·실적추출 부르기)에
`alwaysOutputData`를 켜서 0건이어도 다음 단계가 이어지게 했다. 뒤
워크플로들은 입력을 읽지 않거나(공시원장·회사공시 시트를 직접 읽음)
`회사명필터`가 없으면 전체를 보므로 빈 항목이 들어가도 동작이 바뀌지
않는다. 발행 버전은 `c75257d7`이다.

### 같은 날 추가: 공시검색의 「DB파일보유」가 늘 false였던 버그 (2026-10-12)

LX세미콘으로 「수집 data」를 열었더니 27건이 전부 「원문 누락」으로 나왔다. 시트에는

## 공시수집기 탭을 실적 관리로 합침 (2026-10-12)

메뉴를 줄이고 한 번 누르면 전부 적용되게 하려고 「공시수집기」 탭을 없애고 실적 관리 한 곳으로 합쳤다.

**화면 구성(실적 관리 탭, 위에서 아래로)**
1. 설명 카드
2. 「수집 data」 카드: 회사 줄의 버튼이나 아래 검색에서 고른 회사의 DART 보고서별 원문 저장·실적 추출·비용 추출 상태와 누락. 평소에는 숨겨져 있다.
3. 그룹 관련 실적, 경쟁사 실적 회사 목록과 「선택 회사 업데이트 실행」
4. 다른 기업 찾기: 옛 공시수집기의 기업 검색(상장·비상장). 고르면 2번 카드가 그 회사로 열린다.
5. 기업 관리: 옛 공시수집기 아래쪽의 등록·수집 종류·알림 설정. 그대로 옮겼다.

**지운 것.** 메뉴의 「공시수집기」 버튼, `tab-disclosure` 패널, 기간·종류 선택, 옛 공시 목록 카드와
`discSaveSelected` 등 저장 함수. 옛 주소나 브라우저에 저장된 탭 이름이 `disclosure`면 `showTab()`이
실적 관리로 보낸다. 목록은 이제 항상 2020-01-01 이후 최근 40건이다(기간 선택을 없앴다).

**저장 한 번에 이어지는 일.** 「수집 data」 카드의 저장 버튼 → `LXGroup_수집저장` →
원문 저장(`db저장`) → 실적추출(회사명필터) → 비용추출(회사명필터). 끝나면 화면이 `loadComp(true)`로
경쟁사 현황·실적현황 자료를 다시 받는다. 일괄 버튼 `LXGroup_실적반영`에도 같은 비용추출 호출을 붙였다.
- `LXGroup_경쟁사_비용추출`(`Qa9mF8rLJd8d28Il`)에 `손으로 부를 때`(executeWorkflowTrigger)를 더했고
  「읽을 보고서 고르기」가 회사명필터를 받으면 12건 상한 없이 그 회사만 처리한다. 금요일 05:10
  자동 실행은 그대로다. 코드를 로컬에서 필터 있음·없음·빈 필터로 시험했다.
- 등록되지 않은 기업은 카드에서 계열사를 고르게 하고 `수집저장`이 그 값을 `db저장`에 넘겨 경쟁사 시트에 등록한다.

**고친 것.** 기업 관리가 실적 관리와 같은 목록 변수(`mgmtCompanies`)를 써서, 실적 관리를 먼저 열면
기업 관리 목록이 비어 보였다. 이미 있으면 다시 받지 않고 그리기만 한다. 계열사 선택은 보고서를 체크할 때 표가
다시 그려져도 유지된다.

**확인한 것.** Playwright로 세 웹훅을 가짜 응답으로 바꿔 시험했다: 메뉴 버튼과 패널이 없음, 옛 탭 이름 전환,
등록 회사 저장 본문, 미등록 회사 계열사 전달, 폴링 종료와 화면 자료 갱신, 기업 관리 목록, 390px 폭.

**확인하지 못한 것.** 올바른 실행 비밀번호로 실제 저장하는 경로(원문 저장 → 실적 → 비용)를 끝까지 돌려 보지 못했다.
비용추출을 회사 필터로 실제 실행한 것도 아니다(로컬 코드 시험만). 처음에는 한 회사, 한 건으로 확인한다.
`LXGroup_경쟁사_마스터정리`(회사별 「실적 마스터」 스프레드시트)는 여전히 주 1회 자동 실행이라 저장 직후에는

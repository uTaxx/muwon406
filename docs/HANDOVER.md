### 종합 상황판(첫 화면)

카드는 모두 `#tab-home`의 직계 자식이고, `설정보이기()`가 `appendChild`로 사용자가
정한 순서대로 다시 배치한다. 기본 순서:

1. **공통 지표** — 환율·금리 등. 아침에 제일 먼저 보는 값이라 맨 위
2. **주요 뉴스** — 가장 최근 수집분 중 메일 발송 기준을 통과한 기사.
   **총점(중요도+관련성+긴급성, 3~15) 내림차순**으로 세우고 기본 5건만 펼친 뒤
   나머지는 「나머지 N건 더보기」로 접는다. 총점이 같으면 최신 기사가 앞
   (`Array.sort`가 안정 정렬이라 날짜순 배열을 총점으로 다시 세우면 자동으로 그렇게 된다)
3. 계열사 카드 (경쟁사 n곳 · 지표 n개 · 최근 7일 기사 n건 + 변동폭 최대 지표 1개)
4. 그룹별 수집 현황 · 5. 실리코시스 요약 — 기본이 2열이라 넓은 화면에서 나란히 선다

**카드 폭**도 설정이 정한다. `설정보이기()`가 `data-col`(1=한 줄 전체, 2=절반)을 찍고
CSS 는 `#tab-home > [data-col="2"]{grid-column:auto}` 하나로 처리한다. 2열 카드가
연달아 오면 그리드 자동 배치가 알아서 짝을 짓는다.

카드 안쪽 격자(`.hi` 지표 칸, `.co-grid` 계열사 카드)는 화면 폭이 아니라
`repeat(auto-fit, minmax(...))`로 **카드가 실제로 가진 폭**에 맞춘다. 화면 폭으로
칸 수를 정하면 절반 폭 카드에서 글자가 잘린다.

KPI 4개(마지막 수집 / 최근 7일 / 중요도 4↑ / 실리코시스 30일)는 **주요 뉴스 카드
머리(`.mail-head`) 안**, 「전체 기사 →」 왼쪽에 `.kpi-mini`로 작게 붙는다. 카드 안에
들어 있어서 순서 목록(`c.순서`)에는 넣지 않고 on/off만 따로 둔다(`CFG_KPI`). 이 때문에
`설정보이기()`의 재배치는 `:scope > [data-card=...]`로 직계 자식만 집는다 — 그냥
`querySelector`로 집으면 요약 숫자가 카드 밖으로 끌려 나온다.

`#tab-home`은 CSS 그리드다. `display:grid`를 `#tab-home.active`에만 거는 이유는
`.tab-panel{display:none}`보다 id 선택자가 세서, `#tab-home{display:grid}`로 두면 다른
탭에 있어도 첫 화면이 보이기 때문이다.

### 대시보드 설정

헤더의 「대시보드 설정」. localStorage(`lx-cfg`)에만 저장하며 서버로 전송하지 않는다.

- **첫 화면 구성** — 카드 5개를 체크로 on/off, ▲▼로 순서 변경, 「1열/2열」 버튼으로
  폭 변경 (`설정순서(통, 사전, 차례, 그릇, 폭그릇, 뒤에)` — `폭그릇`이 null 이면
  폭 버튼을 그리지 않는다. 계열사 하위 탭이 그 경우다)
- 요약 숫자 4개 on/off (`#cfgKpi`, 순서 변경 대상이 아님)
- 주요 뉴스 기준(중요도/관련성/긴급성)
- 주요 뉴스 표시 방식 — 먼저 펼칠 건수(기본 5), 최대 건수(기본 15),
  정렬(`score` 총점순 / `date` 최신순)
- **계열사 화면 구성** — 하위 탭 4개 on/off + 순서 변경. 맨 위 탭이 기본 진입 탭
- 표시할 계열사 on/off
- 기본값 복원 버튼

**저장 버튼은 없다.** 값이 바뀔 때마다 `설정저장()`이 곧바로 localStorage 에 쓴다.
대신 화면 아래에 붙는 `.cfg-bar`(sticky)에 마지막 저장 시각을 적는다. `설정저장()`은
`기억()`을 쓰지 않고 `localStorage.setItem`을 직접 호출한다 — `기억()`이 실패를
삼켜서 성공 여부를 알 수 없기 때문이다. 실패하면(시크릿 모드 등) 띠가 붉게 바뀌며
창을 닫으면 설정이 사라진다고 알린다.

저장 형태:
```
{ 순서:['ind','mail','co','groups','risk'], home:{...,kpi},
  폭:{mail:1,co:1,ind:1,groups:2,risk:2},
  판:2, 하위순서:['group','index','comp','risk'], sub:{...}, 계열사:{...},
  기준:{중요도,관련성,긴급성,손댐,읽었나}, 뉴스수:15, 첫뉴스수:5, 정렬:'score' }
```
`순서맞추기()`가 저장된 배열에서 모르는 이름을 버리고 빠진 것을 기본 순서대로 뒤에
붙인다. `폭맞추기()`는 1도 2도 아닌 값을 기본으로 되돌린다.

**`CFG_판`**: 기본 차례를 바꿔도 이미 쓰던 사람의 저장값이 이기므로 새 기본값이 닿지
않는다. 판을 올리면 `판올리기()`가 저장된 `하위순서`와 `lx-co-sub`만 한 번 버린다.
`coSub`가 스크립트 위쪽에서 곧바로 정해지므로 `설정()` 안이 아니라 그보다 앞에서 돈다.
카드 순서·폭·뉴스 기준은 사람이 정한 것이라 건드리지 않는다. 둘 다 있어서 카드를
새로 넣거나 없앤 뒤에도 옛 설정이 그대로 동작한다.

**카드를 새로 넣는 법**: ① `#tab-home` 안에 `data-card="키"`를 단 `<section class="card">`
추가 ② `CFG_HOME`에 한 줄 ③ `CFG_기본.순서`·`CFG_기본.home`·`CFG_기본.폭`에 그 키 추가
④ `renderHome()`에서 그리는 함수 호출. 저장돼 있던 옛 설정에는 없는 키라 순서 맨 뒤에
기본 폭으로 붙는다.

기준값은 신청/변경 화면을 한 번 열면 그 계정 설정을 가져다 쓴다. 사용자가 설정에서
직접 조정하면 그 뒤로는 덮어쓰지 않는다(`기준.손댐` 플래그).

## 4. 리스크 관리 구조

`LX_Group_MI_Setting`의 **`리스크` 시트** 한 줄이 곧 대시보드의 리스크 하나다.
코드 수정 없이 시트만으로 추가·수정할 수 있다.

컬럼: `계열사 · 리스크명 · 사용 · 키워드 · 설명 · 사건원장 · 비고`

- **키워드**: 쉼표 구분. 기사의 제목/매칭어/그룹명/요약에 대해 부분 일치로 검사한다.
  **그룹명을 넣으면 그 그룹 기사 전체가 포함된다.**
- **사건원장**: `TRUE`면 「주요 소송 사건 · 책임 배분」 카드가 함께 표시된다.
  현재 실리코시스만 `TRUE`.
- 한 계열사에 여러 줄이 있으면 화면 위쪽에 선택 버튼이 생긴다.

**현재 등록: 1줄 (하우시스 / 미국 엔지니어드스톤 리스크 / 키워드 24개 / 308건 매칭)**

나머지 6개 계열사는 빈 화면 상태이며, 화면에서 시트와 드라이브 폴더로 바로 이동할 수
있는 링크를 제공한다.

## 5. 다음 할 일

### A. 계열사별 리스크 등록 (보류 중 — 사용자 결정 대기)

사용자가 테마를 지정했고, 키워드 초안까지 만들었으나 **아무것도 반영하지 않은 상태**다.

| 계열사 | 테마 |
|---|---|
| 인터 | 인도네시아 정세 (자원·정책 리스크) |
| 판토스 | 이란 전쟁 등 해상 경로 이슈와 운임 변동 |
| 글라스 | 중국·인도산 반덤핑 |
| MMA | 중국산 수입량·증설 |
| 세미콘 | 디스플레이 시장 증감 (DDI 수요) |
| 하우시스 | 실리코시스 (현행 유지) |

**핵심 제약**: 리스크 탭은 수집 그룹이 있어야 동작한다. 실리코시스가 308건인 이유는
`해외_주요이슈` 전용 수집 그룹이 있기 때문이다. 위 5개 테마를 현재 코퍼스(2,506건)에
대고 측정하면 1~4건이고 대부분 오탐이다.

따라서 리스크 하나당 두 가지가 필요하다:
1. 신청/변경 화면에 **수집 그룹** 추가 (키워드 문법: `+` 필수포함, `-` 제외)
2. `리스크` 시트에 **한 줄** 추가 (그룹명 + 고유 단어 몇 개)

**미결 사항**: 수집 그룹을 만들면 그 기사가 팀 메일·텔레그램에도 발송된다.
현재 하루 139건 수집 → 98건이 기준 통과해 메일에 실린다. 선택지는
(a) AI 평가 켬 = 점수가 붙어 리스크 화면이 온전히 동작, 메일도 늘어남
(b) AI 평가 끔 = 메일 그대로, 리스크 화면에 중요도·별점 없음
(c) 인터·판토스만 먼저 1주일 시험 ← 권장
사용자가 "일단 아무것도 반영하지 마"라고 지시해 대기 중이다.

키워드 초안은 세션 대화에 있으며, 설계 원칙은 다음과 같다:
- 짧은 토막 금지. `DDI`는 `BuildDirect` 안에 부분 일치해 걸린다. `MMA`는 격투기·
  공시를 물어온다. `증설` 단독은 데이터센터 기사를 대량으로 끌어온다.
- 두 단어 이상의 고유한 표현을 쓴다(`산림 훼손`, `해상운임`, `상계관세`).
- 모호한 기준어는 `+`로 묶는다(`인도네시아+니켈`). `인도네시아` 단독은 판토스
  인도네시아 CSR 기사 7건이 걸렸다.

### B. 그룹 실적 — LX판토스·LX글라스 실적 추출 (미해결)

**2026-09-07 조사 결과**: 일곱 계열사 모두 `경쟁사` 시트에 `우리편=TRUE`로 이미
등록돼 있었다. 화면에 안 뜬 까닭은 등록이 아니라 다음 둘이었다.

1. **조회 웹훅이 「전사」 줄을 버렸다 (고침)** — 부문표가 없는 회사는 추출기가 요약
   손익의 전사 값을 부문 이름 없이(또는 `—`) 남기는데, `LXGroup_경쟁사_조회`의
   `답 만들기` 부문 필터가 그것을 쓰레기로 보고 버렸다. 뒤에 `전사 보태기` 노드를
   붙여, 부문이 하나도 안 잡힌 회사만 「전사」 한 줄로 되살린다. 이것으로
   **LX세미콘·LX MMA**가 살아났고 경쟁사 쪽에서도 8곳(현대글로비스·SK네트웍스·
   아나패스·금호석유화학·대한유화·이건창호 등)이 함께 살아났다.
2. **LX판토스·LX글라스는 숫자 자체가 없다 (미해결)** — `경쟁사실적` 시트의 그
   회사 줄은 전부 `단위='부문표 못 찾음'`, `사업연도` 빈 값, 매출·영업이익 빈 값이다.
   드라이브의 원문을 열어 보면 연결손익계산서(표 #14)가 분명히 있고
   `I. 매출액 8,063,339,457,044` / `V. 영업이익 221,870,372,041`이 들어 있다.
   못 뽑는 까닭은 둘로 보인다:
   - 기간 머리글이 `제 48(당)기 / 제 47(전)기`라 **연도를 알 수 없다**(`사업연도`가 빈 값).
     보고서명 `감사보고서 (2024.12)`에서 연도를 끌어와야 한다.
   - 값이 **원 단위**라 억원으로 나누어야 한다(다른 회사는 백만원·억원 표기).

   고치려면 `LXGroup_경쟁사_실적추출`(`MHGVBh9mKGzzUobP`)의 요약 손익 대체 경로를
   손봐야 하는데, 그 노드는 22개 회사 전부가 쓰므로 잘못 건드리면 경쟁사 성과 화면이
   통째로 흔들린다. **사용자 확인 뒤 착수한다.**

`LX홀딩스`는 시트에 `사용=FALSE`다(줄 2, 메모: "지주사 연결. 필요해지면 사용을
TRUE 로"). 켜면 그룹 실적에 지주사 연결 실적이 들어오는데, 자회사 매출을 다시 한 번
세는 셈이라 나란히 놓으면 오해를 부른다. **이것도 사용자 판단이 필요하다.**

### D. 문체 정리 (완료)

`README.md`·`hub.html`·`manual.html`·`docs/`의 부자연스러운 순우리말 어휘를 표준
용어로 모두 바꿨다(2026-09-06). `hub.html`에서는 주석뿐 아니라 식별자도 함께 바꿨다:

| 옛 이름 | 새 이름 |
|---|---|
| `고르개` (함수) | `설정선택` |
| `고르개` (지역 변수) | `선택버튼` |
| `돈고르개` / `모양고르개` / `기간고르개` | `통화선택` / `모양선택` / `기간선택` |
| `단추` / `옛단추` | `버튼` / `옛부문버튼` |
| `말썽` | `오류메시지` |
| `리스크낱말` / `집낱말` / `낱말` | `리스크키워드` / `집키워드` / `키워드` |
| `갈래` | `구분` |

`encodeURIComponent('갈래')` 문자열 하나만 남겨 뒀다 — `LXGroup_원본내려받기` 웹훅이
받는 질의 파라미터 이름이라 바꾸면 다운로드가 깨진다.

`눈금`(축 눈금), `띠`(막대 옆 표시 띠)는 표준 한국어라 그대로 뒀다.

검증: `찍기.mjs`(가로 넘침·JS 에러 없음), `계열사.mjs`(13개 항목 통과),
`설정.mjs`(18개 항목 통과).

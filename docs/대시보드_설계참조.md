# 대시보드 설계 참조 (Phase 8용)

사용자가 제시한 모바일 목업을 옮겨 적은 문서. **아직 구현하지 않는다** —
전략 엔진(Phase 5~6)이 끝난 뒤 착수할 때 이 문서를 기준으로 삼는다.

## 1. 전체 구조

두 화면짜리 모바일 앱 형태. 하단 탭 5개로 나뉜다.

```
┌────────────────────────────────────────┐
│  제목 (굵게)              🔔 ❓ ⚙️      │
│  부제 (연한 회색)                       │
├────────────────────────────────────────┤
│                                        │
│            (화면 내용)                  │
│                                        │
├────────────────────────────────────────┤
│  🏠      📈      📋      🔔      👤     │
│ 대시보드  전략    기록    알림    관리    │
└────────────────────────────────────────┘
```

- 알림 아이콘에는 **빨간 점(미확인 표시)**
- 현재 탭만 파란색, 나머지는 회색 아웃라인

## 2. 대시보드 탭

부제: "자주 쓰는 항목 중심"

### 상단 요약 카드 4개 (가로 스크롤)

| 카드 | 값 | 배지/보조 |
|---|---|---|
| 전략 | 3개 활성 | `LIVE` (보라) |
| API 연결 | 정상 | `연결됨` (초록) |
| 오늘 손익 | +1.8% | 누적 수익률 |
| 최근 동기화 | 12:41 | 방금 전 |

각 카드 왼쪽에 파스텔 배경의 둥근 아이콘 칩(보라/초록/파랑/주황).

### 접이식 목록 (아이콘 + 제목 + 설명 + 배지 + ⌄)

| 항목 | 설명 | 배지 |
|---|---|---|
| 활성 전략 | 실거래 적용 전략 설정 | `LIVE` `3개` |
| 보유 종목 & 최근 주문 | 잔고와 최신 체결 현황 | `3건` |
| 매매 기록 | 전략별 청산 완료 거래 | `128건` |
| 전략 리뷰 결과 | 다른 전략과의 비교 분석 | `최신` |
| 리스크 정책 | 손절 · 비중 · 노출 한도 | `정상` |

## 3. 관리 탭

부제: "설정 및 운영 관리". 접이식이 아니라 **다음 화면으로 넘어가는(›) 목록**.

| 항목 | 설명 | 배지 |
|---|---|---|
| KIS 인증정보 | API 키 및 계좌 연결 상태 | `연결됨` |
| 텔레그램 알림 | 체결 · 오류 · 리포트 알림 | `정상` |
| 변경 이력 | 설정 변경 기록 · 5초마다 자동 갱신 | `방금 전` |
| 개발 로그 | git 커밋 · 20초마다 자동 갱신 | `방금 전` |
| 앱 설정 | 언어 · 테마 · 보안 등 일반 설정 | — |

## 4. 시각 언어

- **배경**: 아주 연한 회색, 카드는 흰색 + 둥근 모서리(16px 내외) + 옅은 그림자
- **아이콘 칩**: 48px 정도의 둥근 사각형, 파스텔 배경 + 진한 아이콘
  (보라=전략, 초록=연결/인증, 파랑=데이터/기록, 주황=시간, 분홍=비교, 청록=텔레그램)
- **상태 배지**: 알약 모양
  - 초록 = 정상/연결됨
  - 보라 = LIVE
  - 파랑 = 건수(3건, 128건)
  - 회색 = 시각(방금 전)
- **여백이 넉넉**하고 한 화면에 5~6줄. 지금 Streamlit 화면처럼 촘촘하지 않다.

## 5. 지금 화면과의 차이 (구현 시 판단할 것)

| 항목 | 지금 | 목업 |
|---|---|---|
| 구조 | 한 페이지에 expander 9개 세로 나열 | 탭 5개 + 요약 먼저 |
| 첫 화면 | 설정부터 보임 | **상태 요약 카드**부터 |
| 설정 | 본문에 섞여 있음 | `관리` 탭으로 분리 |
| 알림 | 없음 | 별도 탭 + 미확인 뱃지 |

## 6. 착수 전에 정해야 할 것

1. **"전략 3개 활성"** — 목업은 전략을 동시에 여러 개 굴리는 걸 전제한다.
   지금은 활성 전략이 **하나**(`strategy.active_key`)다. 여러 전략을 동시에
   운용하려면 자본 배분·중복 진입·성과 귀속을 어떻게 할지부터 정해야 한다.
   화면보다 엔진 쪽 결정이다.
2. **하단 탭 바** — Streamlit에 기본 제공되는 위젯이 아니다. 상단 `st.tabs`로
   대체하거나 CSS를 직접 넣어야 한다. 목업 그대로는 공짜가 아니다.
3. **"오늘 손익 +1.8%"** — 지금은 평가금액만 저장한다. 일간 수익률을 화면에
   쓰려면 기준 시점(전일 종가 기준인지 당일 시가 기준인지)을 정해야 한다.
4. **알림 탭** — 텔레그램으로 나가는 알림을 앱 안에도 쌓을지. 쌓는다면 읽음
   처리 상태를 저장할 테이블이 하나 필요하다.

# 문서 문체 정리 (2026-10-19)

저장소 문서에 남아 있던 어색한 표현을 일반적인 한국어 실무 문체로 고쳤다. 이 문서는 무엇을 왜 어떻게 바꿨는지, 무엇을 일부러 남겼는지를 적는다. 바꾼 문장 전체는 `docs/문체_정리_변경목록_2026-10-19.md`에 있다.

## 1. 배경

- `CLAUDE.md`의 글쓰기 규칙은 `README.md`·`hub.html`·`manual.html`·`docs/`에서 금지어를 모두 정리했다고 적고 있었다(2026-09-06). 실제로는 `docs/HANDOVER.md`와 `README.md`에 순우리말 조어와 어색한 표현이 많이 남아 있었다.
- 새 세션은 이 문서를 먼저 읽기 때문에 문서의 어휘와 문체를 그대로 따라 쓰게 된다. 2026-10-19 세션에서 쓴 보고와 인수인계 문장에도 같은 영향이 있었다.

## 2. 고친 기준

**고친 것 (산문만)**

- `CLAUDE.md` 표의 금지어와 같은 계통: 칸·줄 → 컬럼·행·셀·영역, 단추 → 버튼, 자료 → 데이터, 갈래 → 종류·구분, 열쇠 → 키, 낱말 → 키워드·단어 등
- 부르다 → 호출하다, 돌려주다 → 반환하다, 뽑다 → 추출하다, 걸러내다 → 필터링하다, 손으로 → 수동으로, 판(版) → 버전, 시간표 → 스케줄, 까닭 → 이유·원인
- 우리말 수 표기 → 숫자: 스물여섯 → 26, 열두 달 → 12개월, 석 달치 → 3개월치, 이레 → 7일, 넉 장 → 4개
- 비유·잠언조 문장을 설명체로: "~것보다 낫다", "빨갛게 끝난다"(→ 실패한다), "머리카락 굵기입니다"(→ 거의 보이지 않을 만큼 얇습니다) 등
- 1인칭 표현("내가 만든 오류" 등)과 의미가 불분명한 신조어

**바꾸지 않은 것**

- 코드 블록, 인라인 코드, 「」로 감싼 UI 라벨·노드 이름·시트·컬럼·워크플로 이름
- 한글 함수·변수 이름(`설정보이기()`, `판올리기()`, `칸()` 등), 웹훅 질의 파라미터 `갈래`
- 파일명·경로·URL, 날짜·숫자·ID·버전 표기, 사실관계와 결론

## 3. 방법

1. 문서를 6개 구간(HANDOVER 4구간, README, 나머지 문서 4개)으로 나눠 검토자 6명이 각각 「원문 → 수정문 → 이유」 목록만 만들었다. 검토자는 문서를 직접 고치지 않았다.
2. 목록을 사본에 적용하면서 자동 검사를 했다.
   - 원문이 문서에서 정확히 한 번만 나오는지, 다른 항목과 겹치지 않는지
   - 코드 블록·인라인 코드·「」 이름·URL이 바뀌지 않았는지(바뀌면 그 항목은 제외)
   - 숫자가 줄어들지 않았는지(늘어난 숫자는 우리말 수 표기를 숫자로 바꾼 것인지 전부 확인)
3. 표본을 직접 읽어 의미가 바뀌지 않았는지 확인했다. 무작위 60건, 부정어 수가 달라진 72건, 길이가 크게 바뀐 항목, 숫자가 늘어난 항목 전체를 봤다.
4. 1차에서 놓친 어휘(머리줄, 표시줄, 선택 줄, 까닭, 열두 달, 손으로 등)는 2차로 직접 고쳤다.

- 「잡혔고, 몇 분 뒤 재확인하니 잡혔다」를 「나타나지 않았고…」로 바꾼 제안은 앞 행의 「바로 안」과 겹쳐 이중 부정이 되므로 「보였고, 몇 분 뒤 다시 확인하니 보였다」로 고쳤다.

- 「승자」를 「최종 폴더」로 바꾸는 제안이 두 행에 걸친 문장 안에서 조각으로 적용돼 「…를 모든 요청이 같은 폴더를 최종 폴더로 선택한다」처럼 문법이 깨졌다(HANDOVER의 폴더 중복 방지 절). 「…를 모든 요청이 똑같이 최종 폴더로 정한다」로 직접 고쳤다. 같은 유형을 찾으려고 수정 부분이 든 전체 행을 무작위로 40개 읽었고 그 밖에는 깨진 문장이 없었다. 전수 확인은 아니다.
- 「(발행)는 갈래가」는 웹훅 파라미터 이름이라 자동 검사에서 제외됐고, 「`갈래` 파라미터가」로 직접 고쳤다.

## 5. 일부러 남긴 것

- 「요약 손익 되줍기」, 「헤드라인 뽑기」, 「읽을 보고서 고르기」처럼 실제 n8n 노드 이름. 이름을 바꾸면 워크플로와 문서가 어긋난다.
- 화면에 실제로 표시되는 고정 문구(「견줄 만한 자료가 아직 없습니다」), 워크플로가 시트에 적는 값(「자료없음」), 워크플로 이름(「무원406 대시보드 자료」)
- 「줄이다」「줄었다」「스케줄」「견줄」「한 줄」「127줄」(코드 줄 수)처럼 정상적으로 쓰인 `줄`.
- 코드 블록 안의 도식에 있는 `줄`(「계열사 줄」, 「탭에 줄 추가」, 「머리줄 처리」). 코드 블록은 바꾸지 않는 원칙이라 두었다. 이 도식 5곳 안팎은 다음에 따로 고칠 수 있다.
- 본문에 남은 `줄` 약 60곳은 위 두 경우뿐임을 확인했다.
- `CLAUDE.md`는 규칙 표 자체라서 바꾸지 않았다.

## 6. 범위 밖이고 확인하지 못한 것

- `hub.html`, `manual.html`, n8n 노드 안의 코드 주석과 노드 설명은 이번에 보지 않았다. `CLAUDE.md`는 이 파일들을 2026-09-06에 정리했다고 하지만 그 뒤에 쓴 주석에는 같은 문제가 있을 수 있다.
- 1,112건 전체를 사람이 일일이 읽지는 않았다. 표본·자동 검사로 의미 변화를 확인했을 뿐이어서 일부 항목에서 의미가 미세하게 달라졌을 수 있다. 전체 목록에서 원문과 수정문을 비교할 수 있다.
- 과거 세션이 쓴 코드 주석과 문서가 서로 다른 이름을 쓰는 곳(예: 코드의 `칸()` 함수와 문서의 「컬럼」)은 이름을 그대로 두었다.

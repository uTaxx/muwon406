# 뉴캐슬 파일럿 6차 — 게재일이 붙은 뉴스 수집 자동화와 뉴스 변수 검증 (2026-10-20)

5차에서 웹 검색 에이전트로 월별 사건을 소급 수집하려 했으나 검색 한도와 연도 확인 문제로 실패했다. 이번에는 게재일이 붙어 있는 구글 뉴스 RSS를 n8n으로 수집해 사건 데이터를 쌓는 구조로 바꿨다.

## 1. 만든 것
- **워크플로우:** `LXGroup_석탄사건수집`(id `VnilrvCvup0JuER4`, 게시됨). 매일 07:10에 최근 4일 구간의 기사를 모아 구글 시트 「석탄 사건 수집」(시트 「기사」)에 쌓는다.
- **구조:** 백필 기간 → 조회 질의 만들기 → 질의 호출 → 기존 기사 읽기 → 기사 정리 → 시트에 쌓기. 백필 기간 노드의 시작·끝 날짜를 비워 두면 일일 모드, 채우면 그 기간을 월 단위 창으로 나누어 받는다(질의 하나가 최대 100건이라 월 단위로 나눈다).
- **질의 6종:** 중국 수입, 중국 증산·안전, 인도네시아, 러시아 제재, 공급 차질, LNG 차질. 북한산 석탄 기사는 해상 발전용 유연탄과 관련이 적어 질의에서 제외했다(첫 시험에서 2016~2017년 기사가 북한산 석탄에 쏠렸다).
- **컬럼:** 기사일(게재일, KST), 수집일시, 질의, 제목, 출처, 링크, 규칙유형, 규칙방향. 규칙유형·규칙방향은 제목 키워드 규칙으로 먼저 붙인 값이고 규칙에 걸리지 않으면 「미분류」다. 방향은 가격 결과가 아니라 사건 종류만으로 정한다.
- **중복 제거:** 링크와 제목 앞 80자로 시트 안에서 거른다. 재실행해도 중복으로 쌓이지 않는 것을 확인했다.
- **오류 알림:** 워크플로우 설정의 오류 워크플로우를 `LXGroup_실패알림`으로 지정했다.
- 이 워크플로우는 API 키를 쓰지 않는다. 구글 시트 연동은 공용 크리덴셜을 쓴다.

## 2. 수집 결과(백필 2016-01~2025-12)
- 기사 5,957건. 120개월 모두 기사가 있고 월 기사 수 중앙값은 37건이다.
- 질의별: 공급 차질 2,395, 러시아 제재 1,579, LNG 차질 794, 중국 수입 597, 인도네시아 352, 중국 증산·안전 240.
- 규칙으로 분류된 기사는 약 11%(671건)이고 나머지 89%는 「미분류」다. 규칙유형이 가장 많은 것은 공급 차질 293, 러시아 석탄 제재 126, LNG 공급 차질 105다.
- 연도별 기사 수가 늘어난다(2016 158건, 2022 1,010건, 2025 1,476건). 구글 뉴스 색인 범위와 질의 포화 때문으로 보이며, 분석에서는 직전 12개월 평균 대비 비율로 바꿔 쓴다.
- 기사 원문 데이터는 저작권 문제로 저장소에 넣지 않았다. 월별 건수만 `뉴스_월별_건수_2016-2025.json`에 저장했다.

## 3. 뉴스 변수 예측 검증
- 방법: 3차와 같은 확장 윈도우 워크포워드(릿지, 평가 시작 2019-06). 입력은 월별·주제별 뉴스량(직전 12개월 평균 대비 로그 비율), 규칙방향점수(규칙 상승 건수 − 하락 건수), 규칙 사건 비중이다. 변동성 예측에는 EWMA 변동성과 직전 월 변동폭을 기준 입력으로 둔다.

| 대상 | 입력 | 평가 월수 | R² | 방향 적중(p) |
|---|---|---|---|---|
| 다음 달 \|변동\| | 변동성만(기준) | 85 | 0.12~0.13 | - |
| 다음 달 \|변동\| | +뉴스 전체량 | 72 | 0.04 | - |
| 다음 달 \|변동\| | +주제별 뉴스량 | 72 | 0.02~0.04 | - |
| 다음 달 수익률 | 변동성만 | 85 | -0.08~-0.02 | 48~52% (0.79~0.81) |
| 다음 달 수익률 | +뉴스 전체량 | 72 | -0.07~0.00 | 53~63% (0.04~0.71) |
| 다음 달 수익률 | +주제별 뉴스량 | 72 | -0.08~0.00 | 58~64% (0.03~0.21) |
| 다음 달 수익률 | +뉴스량+규칙방향 | 72 | -0.07~0.00 | 56~58% (0.20~0.40) |

- 뉴스 변수를 넣으면 변동폭 예측이 오히려 나빠졌다(R² 0.12 → 0.02~0.04). 뉴스량은 다음 달 변동폭을 설명하지 못했다. 평가 월수가 85에서 72로 줄어 직접 비교는 엄밀하지 않지만 방향은 분명하다.
- 방향 적중이 58~64%이고 p값이 0.03~0.04인 설정이 두 개 있으나 8개 설정 중 일부이고 R²는 0 이하라 우연 범위로 본다.
- 단순 상관(월 108개): 다음 달 \|변동\|과의 상관은 러시아 제재 뉴스량 0.16, 중국 수입 0.11, 나머지는 0.07 이하다. 같은 달 \|변동\|과의 상관은 중국 증산·안전 0.28, 러시아 제재 0.14다(동행 관계). 규칙방향점수와 다음 달 수익률 상관은 0.15다.

## 4. 해석
- 뉴스량과 규칙 기반 방향 점수만으로는 다음 달 방향과 변동폭을 예측하지 못한다. 동행 관계(같은 달 중국 증산·안전 뉴스량과 변동폭 0.28)는 있으나 선행 관계는 약하다.
- 한계: 규칙이 분류한 기사는 11%뿐이라 방향 점수가 거칠다. 구글 뉴스 검색의 질의별 100건 상한과 색인 변화가 뉴스량에 섞인다. 제목 규칙이 완화·강화나 무관한 기사를 오분류하는 경우도 있다(예: 러시아 제재 완화 기사를 제재로 분류하던 문제는 완화 규칙으로 보강했다).
- 이 결과는 1~5차와 같은 방향이다. 방향 예측은 어렵고, 변동폭은 과거 변동성 기반으로만 일부 개선된다.

## 5. 다음 단계
1. **일일 수집 운영:** 워크플로우가 매일 쌓는 데이터로 규칙 보강과 재검증을 한다. 규칙에 걸리지 않는 89%는 AI 분류(Claude API)로 유형·방향·중요도를 붙이는 것을 검토한다. 이 경우 API 키는 n8n 크리덴셜로만 두고 저장소에는 넣지 않는다.
2. **정량 변수 확충:** 중국 항만·발전소 재고, 수입량, 운임, 호주·인도네시아 수출량 등 공개 통계를 월 단위로 모아 모델에 넣는다. 이 단계가 방향 예측의 핵심으로 보인다.
3. **spread 기능:** 방향 예측이 확보되기 전까지 변동성 기반 범위와 최근 사건 목록(수집 시트)을 함께 보여 주는 형태로 설계한다.
4. **ICI4·ICI5 전환:** 구독 데이터로 같은 검증을 반복한다.

## 6. 운영 메모
- 시트 「석탄 사건 수집」은 개인 드라이브에 있으며, 시트 ID는 `LXGroup_석탄사건수집`의 두 구글 시트 노드에 들어 있다.
- 과거 데이터를 더 채우려면 「백필 기간」 노드에 시작·끝 날짜를 넣고 수동 실행한 뒤 반드시 비워 둔다(비우지 않으면 일일 실행이 과거 구간을 다시 받는다). 한 번에 24개월(약 4분)까지 안전하게 실행됐다.
- 테스트용으로 만든 임시 워크플로우 `TMP_석탄사건시트생성`은 보관(archive) 처리했고, 첫 시험용 시트는 휴지통으로 옮겼다.
